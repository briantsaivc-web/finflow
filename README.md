# FinFlow 財商沙盒

台灣在地化的財商桌遊（數位版）。單一 HTML 檔、零相依套件、可離線遊玩，專為 iPad Safari 與 PC 瀏覽器設計，全程繁體中文。

**目前版本：v2.31.0-S24**　·　線上試玩：https://briantsaivc-web.github.io/finflow/

## 怎麼玩

用瀏覽器打開 `index.html` 就是完整遊戲——不用安裝、不用網路、不用伺服器。

擲骰前進、抓住機會、管理現金流，從「底層牛馬區」畢業走上「夢想圈」去完成夢想。一局預設 99 輪，結束前可以選擇延長。

內建機制：

- **股市**：四層股價模型（大環境 × 個股股性 × 隨機 × 重大事件）、現股與融資分倉、定期定額、股息再投入、下市與清算、交易成本與融資紀律閘門
- **資產**：房地產、事業、數位資產；每筆資產都看得到現金報酬率與資產報酬率（自備款與貸款分開算）
- **金融**：貸款與浮動利率、信用評級、通膨、景氣循環（復甦／過熱／衰退／蕭條）
- **玩家互動**：拍賣、合資、P2P 借貸、機會轉介
- **人生**：人生商城與保險、品格帳本、學習與準備系統（進修／技能／資格續期／第二人生）、成就與徽章
- **勝負**：幸福感與夢想的圓滿條件、破產與紓困、最後手段
- **對手**：多種性格的電腦玩家（穩健／槓桿／創投），可隨時交給電腦代打再接回
- **進階金融（M9，進階難度以上）**：期貨（可作多放空、十倍槓桿、保證金追繳與強制平倉）——要先有持股經驗或學會衍生性商品才解鎖
- **多人連線**：各自裝置同局（見下方）

每輪結束會出一張結算彙總，把該輪所有異動連同現金／資產／負債／收入／支出的變化一次列清楚，並分成**系統與大環境／你自己的動作／其他玩家引發**三段各自小計；整局的每輪紀錄在結束總結畫面可以逐位玩家回看。景氣、利率、政策這類全場廣播的資訊一律收進彙總，只有需要你當下處理的事（追繳、被拒、出價、邀約）才會即時跳出來。

詳細規則見 `manual/`：

- 《快速上手指南》（3 頁，給第一次玩的人）——或者直接在遊戲裡按 ❔ → 🎓 互動教學
- 《完整規則手冊》（13 頁，20 節，給想搞懂所有機制的人）

兩份都對應 v2.31.0-S24；HTML 原始檔在 `manual/`，改完跑 `node manual/topdf.js` 重新產出 PDF（需要 playwright 與 CJK 字型）。

## 多人連線

兩種模式，開房時選：

- **同機測試**：同一台電腦開多個分頁，各自一個座位。不需要任何設定，用來排練流程。
- **跨裝置**：每人一台設備連同一間房。需要自備 Firebase Realtime Database 金鑰，在「多人連線 → ⚙ 連線設定」填入即可——設定步驟見 `docs/Firebase設定指南.md`。

同步的是**動作序列**不是遊戲狀態（lockstep），所以每台裝置各自重放出同一局；房號 4 碼。加入房間時會比對版本號，版本不一致會被擋下並提示重新整理——所以整桌請從同一個網址開，不要各自拿舊檔案。

## 部署

任選一種，都是把單一檔案放上去而已：

- **GitHub Pages**（現行做法）：Settings → Pages → Source 選 `main` 分支、資料夾選 `/ (root)`，之後每次 push 到 `main` 幾分鐘後自動更新 https://briantsaivc-web.github.io/finflow/
- **Netlify**：把 `index.html` 拖進 Netlify 部署頁即完成
- **隨身碟／AirDrop**：直接把 `index.html` 傳到目標裝置，用瀏覽器開啟

## 專案結構（S21 起拆成源碼層＋打包）

```

card_editor.html  視覺化卡片工坊（同樣由 build/bundle.js 從 src/data 打包，內嵌的卡包不會與遊戲漂移）
src/              源碼層（資料、邏輯、連線、介面分離）
  ├── data/       【資料層】11 個獨立卡包 JSON (base, mall, skill...) 與平衡參數
  ├── engine/     【邏輯層】純函數狀態機 (applyAction)、複式記帳 (ledger)、AI 決策與平衡模擬
  ├── network/    【連線層】多人 Lockstep 同步與 Firebase RTDB 適配器
  ├── ui/         【介面層】DOM 渲染、CSS 樣式表、S20 互動教學
  └── editor/     【編輯器】卡片工坊原始檔

manual/           快速上手指南與完整規則手冊（HTML 原始檔＋PDF）
docs/             歷次變更說明（一期 → S22）＋ Firebase 設定指南
tests/            自動化測試（見下方）
```

## 測試

先裝瀏覽器驅動（介面測試需要）：

```bash
npm install
npx playwright install chromium
```

### 引擎層（Node，不開瀏覽器）

```bash
node tests/contentcheck.js  # 內容包靜態檢查：id 唯一、op 引擎認得、欄位名、金額量級、程式寫死的 id（npm run build 會先跑它）
python3 tests/extract.py    # 從 index.html 抽出引擎層（前三個 script 區塊）
node tests/gate.js          # 1000 局壓力：NaN／Infinity／死結／分錄不平 都必須是 0
node tests/simtest.js       # 500 局平衡指紋，輸出自由圈規格 v0.2 的六項指標
```

`tests/extract.py` 只抽前三個 script 區塊（引擎、動作處理、內容與模擬器）。第四塊之後是介面層與連線層，會碰 DOM，不能在 Node 裡跑——介面要驗請用下面的瀏覽器測試。

## 設計鐵律（改程式前必讀）

1. **Reducer 純函數**：遊戲狀態只由動作推進，隨機數一律走 `util.rand(S)`（種子化）——同一顆種子＋同一串動作，重放必得同一局。引擎層不讀寫 DOM、不用 `Date.now()`。
2. **資料驅動**：所有數值參數都在 `config-default` JSON 區塊，不寫死在程式裡。
3. **帳本即真相**：現金、資產、負債的每一筆變動都過分類帳，帳目永遠要平；`ledger.recompute(p)` 是唯一的推導入口。資產存的一律是**淨額**（房地產存租金減成本、事業存淨利），所以營運成本上升會表現為收入下降，不是支出增加。
4. **開關全關要能位元重現基線**：任何行為變更都掛在 config 開關後面，開關全關時跑 `tests/simtest.js` 必須與上一版數字逐項相同。這條是 S15b 用血換來的——當時直接改了內容資料的數值而沒有掛開關，基線就再也回不去了。
5. **NPC 跑不到的路徑等於沒被測到**：只有真人會走的操作（主動進修、買新創、非回合動作、跨座位決策）必須有直接呼叫引擎的測試，不能只靠對局模擬。這條是 M8S2b 與 S15d 兩次踩坑換來的。
6. **先量再改**：版面與體驗的判斷要有數字。S18 原本要把玩家卡改成一排三個，量下來在 4 人局跟兩欄完全一樣（同樣 2 排、同樣 361px），真正吃掉高度的是卡片本身——改對地方之後系統訊息從看得到 11 則變成 14 則全看得到。

# FinFlow 變更說明 — C2 事業報酬平衡(v2.3.1-C2)

日期:2026-08-28　·　基底:v2.3.1-C1　·　來源:Brian 實測回饋「沒幾輪就進夢想圈,後來又跌回來——事業年化是不是太高、脫離現實?」

## 根因(數據診斷,非猜測)

Brian 的直覺是對的,而且問題比卡面數字更深:設定檔有一個全域參數 **`assetIncomeMult = 2.0`(資產現金流係數,標註「平衡收斂值」)**——所有資產的月現金流在買入時一律 ×2。所以:

- 事業卡卡面年化 40–52%,**遊戲內實際 80–104%/年,12–15 個月回本**(大額 54–67%)。
- 對照不動產:×2 之後全款淨年化也只有 12–21%,而且要吃修繕(每發薪 6% 機率、1–3 個月租金)與衰退期空租;**事業卻完全沒有營運風險**(修繕/空租只打不動產),唯一下修只有景氣係數(衰退 ×0.8/蕭條 ×0.65)。
- 另發現 `volatileProfit`(獲利波動)旗標**只有 UI 顯示「獲利波動」標籤,引擎沒有任何實作**——標了波動的事業實際上和沒標的一樣穩。此為既有 latent 現象,本次未處理,列入待辦。

模擬佐證(60 局 × 3 NPC,180 玩家人次):現況進圈率 64%、進圈中位 41 輪、進圈者 15% 跌回——「快進快跌」與 Brian 體感一致。敏感度:全域係數降 1.6/1.3/1.0 時進圈中位 45/50/59 輪。

現實對照:小吃攤頂讓 2–3 年回本(年化 33–50%)在現實中存在,但那**包含攤主自己的全職勞務**;遊戲裡玩家保有本業薪水、事業是純被動收入,純被動 80–100% 年化確實脫離現實。

## 修法(Brian 選定:事業獨立係數 1.3)

新增 config 參數 **`bizIncomeMult = 1.3`**(調參面板「平衡」組,0.3–3 可調):BUSINESS 類資產的月現金流改用此係數,與不動產脫鉤;**不動產維持 assetIncomeMult=2.0 不動**。修正後事業實際年化:小額 53–68%(回本 18–23 個月)、大額 35–44%(回本 28–30 個月)——仍然優於不動產(補償其無帳面增值、退出折價),但不再輾壓。

引擎實作:新增 `E.incomeMultFor(S, kind)` helper(BUSINESS→bizIncomeMult,缺省回退 assetIncomeMult),七處落點全部改走 helper:買入結算(buyAsset)、二選一比較(oppCompare)、轉介介紹費/拍賣估值(oppIncome)、NPC 估值、UI 買入預覽(buySimple)、自測 JV 事業分割斷言。合資(JV)因走 payload 分割後再 buyAsset,自動繼承。

## 驗證

- 錨點式 patch(patch_c2.py)九處替換全部唯一命中;node --check 全部 JS 區塊通過;殘留掃描確認引擎內已無 BUSINESS×assetIncomeMult 的乘法。
- 官方自測 **35/35**;模擬 40 局零例外零 NaN。
- 單元驗證:買入嘉義火雞肉飯(8.5/月)→ monthlyIncome=11.05(=8.5×1.3)✓;買入台南店面 → 28.2(=15×2−1.8,維持 ×2)✓。
- 平衡統計(60 局,同 seed 集對照):進圈率 64%→49%、進圈中位 41→53 輪、跌回率 15%→11%。局長中位 59→70 輪(遊戲變長,更接近 maxTurns=72 的完整弧線)。

## 部署與注意

`FinFlow_M12A_V4C2_index.html` 拖上 Netlify、各裝置重新整理;Firebase 不用動。參數變動會影響開新局的手感,舊自動存檔重放用的是存檔內的 config,不受影響。若玩後覺得 1.3 太緊/太鬆,調參面板「平衡→事業現金流係數」可即場調,不用改版。

## 待辦(未在本版處理)

1. `volatileProfit` 死旗標:若要讓「獲利波動」真的有感(每月 ±30% 隨機、衰退期偏空),需要一個獨立引擎期別,跟我說一聲即可。
2. 畢業門檻目前仍是被動收入 ≥ 支出 ×1.0(「剛好及格就能衝」);若跌回率希望再降,可加 graduateBufferMult 參數(例 1.25)。

# FinFlow V11.1 變更說明 — 理賠明細與幸福感明細（v2.1.1，2026-08-27）

回答你的問題：**有保險遇到醫療，確實有好處，而且折抵與理賠會疊加**——但舊版只在卡片上顯示一個結果數字（−25,200），完全看不出這是打過折的價格。現在把整筆帳攤開來給玩家看。

## ① 理賠明細：原價 → 折抵 → 理賠 → 實付 → 省下

醫療／意外類事件卡新增一張明細表。以你截圖那筆「植牙自費療程」為例（你當時同時有醫療意外險與健身中）：

| | 金額 |
|---|---|
| ① 原價（帳單金額） | 60,000 |
| ② 健康折抵（健身／健檢 −30%） | −18,000 |
| ③ 醫療＋意外險理賠（60%） | −25,200 |
| ④ **實際支付** | **16,800** |
| 　　合計省下 | **43,200** |

底下接一句未雨綢繆的話：

> 這 43,200 不是運氣，是你**在出事之前**就付出去的保費與健身費換來的。
> **未雨綢繆的意思就是這個：**風險發生的那一天，你能做的事已經在很久以前做完了。

**沒有保險時也會顯示這張表**（這才是教學重點）：標題變成「⚠ 這筆醫療支出，你全額自付」，並多一行對照——「如果當初有投保醫療＋意外險，這一筆可以理賠 X，你只要付 Y」，最後接：「保險要在還用不到的時候買，等用得到的時候就來不及了。」

實作上是在 `applyEffects` 的折抵／理賠流程中把每一段記進 `claimOut`，由 `E.summarizeClaims` 彙總後掛在事件卡的決策物件上，UI 再渲染成表格——**數字不是 UI 自己算的**，是引擎實際結算的那一份，所以永遠與現金變動一致（T-28 有鎖）。

順帶釐清折抵順序：**先健康折抵，再保險理賠**（理賠是按折抵後的金額算），所以兩者疊加不會超額理賠。

## ② 幸福感明細：點下去看每一點從哪來

點右欄的**「幸福感」**、**「品格」**或**「獲勝條件」**任一處，就會打開明細視窗：

| 來源 | 內容 | 點數 |
|---|---|---|
| 👶 家庭 | 小孩 N 位 × 3 點 | +3N |
| ⭐ 品格四軸 | 情緒修養／守法謹慎／子女教養／孝親家庭 各級 | 各 +1 |
| ✨ 夢想進度 | 已完成 x／5 點 | +x |
| 🎁 生活享受 | 買下的享受型消費 N 次 | +N |
| 🛍 商城正向活動 | 進修／健康／人情／比賽 N 項 | 各卡設定 |
| **合計** | 已達門檻／還差 N 點 | **x ／ 10** |

未達門檻時，下方會列出**還能從哪裡補**（商城各品項各加幾點、品格卡每級 +1、夢想進度每點同時 +1、生活享受也算數），並顯示目前生效中的保險與健康狀態。

## 假設與備註

- 明細視窗對「檢視他人財報」也適用（點別人的玩家欄再點幸福感，看得到對手的組成）。
- 理賠明細只在事件實際產生**一次性現金支出**時出現；純敘事或收入型事件不顯示。
- 貴人相助（幸福盲盒）的減免仍在保險之前結算，三者可同時發生，明細以健康折抵與保險理賠兩列呈現（貴人的減免已反映在原價之後的金額裡）。

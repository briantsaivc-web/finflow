## 0. 這一版最重要的一件事：修掉實測回報的死當

**現象**：畫面停在「等待 槓桿哥 做決定中…」，誰也動不了。

**根因（已定位，非推測）**：`E.tickDelist` 跑在 `M1.onRoundEnd`，當投機股跌破門檻進入下市警示時，它把 `DELIST_WARN` 決策卡**推給所有持股者**。但引擎有一條不變式：

> 待決策一定屬於當前玩家。

因為 `ui.tick` 只驅動 `E.activePlayer(S)`（`if(!p.isNPC) return;`），而畫面等的是 `pendingDecision.playerId`。當決策的擁有者是「沒輪到的電腦玩家」時，兩邊互等，整局凍住。使用者猜的方向是對的——確實跟投機股接近下市有關，但真正的錯不在下市判定，而在決策卡被推給了錯的人。

**修法**：警示不再當場推卡，改記在玩家身上，等輪到他自己時才跳。

```js
// E.tickDelist：只記，不推
S.players.forEach(function(pl){
  if(pl.bankrupt) return;
  if(!pl.assets.some(function(a){ return a.kind==="STOCK" && a.symbol===sym; })) return;
  pl.pendingDelistWarn = { symbol:sym, until:S.turnNumber+warnT };
});

// 新增 E.tickDelistWarn(S,p)，由 E.beginTurn 呼叫：
//   已下市／警示已解除／股票已賣掉／玩家已破產 → 直接清掉不跳卡
```

`E.makePlayer` 新增 `pendingDelistWarn:null`；`E.beginTurn` 在 `E.tickRenewals` 之後呼叫 `E.tickDelistWarn`。

**為什麼過去沒抓到**：`sim.playOne` 遇到被拒的動作會自動改送 `END_TURN` 把問題蓋掉，測不出「有真人在場」的驅動語意。

## 1. 本次使用者提出的四項

### (1) 讓電腦玩家也買股票與新創

新增 `npc.stockTrade(S,p)`（決定論，走 `util.randAux`），在電腦回合結束流程中執行：

- 依性格選標的：`NPC_SAFE` 偏穩定股、`NPC_LEVER` 偏成長股、`NPC_VC` 才碰投機股
- 會停利（獲利達門檻落袋）
- 不接刀（急跌中不進場）
- 現金水位不足不出手

新創方面，新增三張**種子輪**卡（`OPS_SU1` 280／`OPS_SU2` 360／`OPS_SU3` 520），因為原本的新創卡最低門檻對電腦玩家的現金水位而言太高，這是它們從不投新創的直接原因。

**必須誠實揭露的代價**：這項改動讓進圈率從 42.8% 掉到 36.2%（−15%，5 個 seed 集的區間不重疊，是真的下降而非雜訊）。已分解確認：新增內容本身中性（42.8 → 42.8），**整段跌幅全部來自電腦玩家開始買股票**——它們現在會賠錢，也會排擠原本投房地產的現金。這是覆蓋率補上後才看得到的真實數字，不是回歸。

### (2) 徽章浮誇些、大些

徽章加上稀有度：傳說 6 張／稀有 5 張／普通 16 張。卡片放大、依稀有度上色（`.badge-card` 系列樣式）。相對頭銜（跟其他玩家比出來的）一律列為傳說級。

### (3) 一期波動是不是太大？穩定股也超大波動

原因找到了：黑天鵝衝擊對**所有股票套同一個跌幅**，穩定股跟投機股一起腰斬。新增 `E.stockBeta`，讓衝擊依個股風險分級：

```js
E.stockBeta = function(S, def){
  if(def && isFinite(def.shockBeta)) return def.shockBeta;
  var ref=E.cfg(S,"shockBetaRef"); if(!(ref>0)) ref=0.06;
  var lo=E.cfg(S,"shockBetaMin");  if(!(lo>0)) lo=0.4;
  var hi=E.cfg(S,"shockBetaMax");  if(!(hi>0)) hi=1.8;
  var v=(def&&def.vol)||ref;
  return Math.max(lo, Math.min(hi, v/ref));
};
```

實測倍率落在 0.47～1.80，同一次衝擊下跌幅 13%～50%。穩定股不再跟著投機股一起崩。

**平時的基礎波動未動**（成長股月 1σ 9%、投機股 16%）。這是設計參數不是缺陷，數據已提供，是否調降請 Brian 決定。

### (4) 每輪紀錄「似乎沒做進去」

查證結果：`ui.showRoundLog` 函式在 v2.7.1 就存在且可用，**但入口看不到**——玩家卡上那個 📜 圖示被放在 `.nm`（`nowrap` + `overflow:hidden`）裡面，被裁掉了。所以功能有做，只是點不到。

修法：移除被裁掉的圖示，玩家卡新增獨立一行「📜 每輪紀錄」（`.lgrow`）。

## 2. 新增測試

### T-58 衝擊分級、電腦進場、徽章稀有度、每輪紀錄
衝擊倍率區間、電腦玩家持股／持有新創人次、可關閉且決定論、徽章稀有度齊全、分錄帶得出輪次與來源。

### T-59 引擎不變式：待決策一定屬於當前玩家（有真人在場也不會卡住）
這是為了這次死當而寫的防線，兩段：

- **(a) 不變式掃描**：6 局逐步跑，任何時刻只要 `decisionQueue` 裡有一張的 `playerId !== S.activePlayerIdx` 就失敗。
- **(b) 死當重現**：8 局，用**跟畫面一樣的驅動語意**——電腦只在輪到自己時才動，真人不主動出手（含記帳題照正解作答，確保不是被測試驅動卡住）。任何一局停滯就失敗。

**反向驗證（把 bug 放回去再測一次）**：

```
FAIL T-57　tickDelist 不得直接推決策（會破壞「待決策屬於當前玩家」的不變式）
FAIL T-59　待決策必須屬於當前玩家，違反：第45輪 DELIST_WARN 屬於 P2 但當前是 P0
```

再把 (a) 關掉、只留 (b)，重現的正是使用者看到的畫面：

```
FAIL T-59　真人回合無事可做也結束不了（phase=DECISION，待決策 DELIST_WARN 屬於 P1）
```

也就是說，(b) 單獨就抓得到這次的死當。

## 4. 未預期發現

1. **每輪紀錄不是沒做，是入口被 CSS 裁掉**。使用者回報「似乎沒做進去」時，第一反應會是去補功能——但先查了 `ui.showRoundLog` 存在與否，才發現是點不到。這種「功能在、入口不在」的缺陷，現有測試完全測不到（測試呼叫的是函式，不是畫面）。**目前無防線**，只能靠實測回報。
2. **NPC 覆蓋盲區的真實成本現在才浮現**。S8 之前所有平衡數字都只反映房地產＋事業兩條路。補上股票之後 −15% 進圈率不是回歸，是**過去的數字本來就偏高**。之後任何「電腦玩家從不走某條路」的發現，都必須當成量測失真處理，不是小事。
3. **仍有 4 人次持有新創（120 人次中）**，種子輪加了之後還是偏低。原因未查證，標 UNKNOWN。

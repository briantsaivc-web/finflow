## 1. 被選中的區內容要正常，其他區翻灰

### 原本怎麼做的（錯在哪）
用一個 `box-shadow: 0 0 0 9999px rgba(6,10,16,.55)` 從高亮框往外撐滿整個畫面來壓暗。
兩個問題：

- **深色主題再壓暗 55%，肉眼幾乎看不出差別**——看起來像整面都灰掉，包含被選中的那一區。
- 這招只能一次圈一塊；自由模式同時圈 15 塊時遮罩會疊加成全黑（S20 已經踩過一次）。

### 改成怎麼做
改成**四片挖洞式遮罩**（`.tutMask`）：焦點框的上、下、左、右各一片，中間留洞。

```css
.tutMask{background:rgba(12,16,22,.55);pointer-events:none;
  -webkit-backdrop-filter:grayscale(1) brightness(.6);backdrop-filter:grayscale(1) brightness(.6)}
```

- 被選中那一區**完全沒有任何東西蓋在上面**，顏色、數字、按鈕都是原本的樣子。
- 其餘區塊**去彩度＋壓暗**（不只是變暗，是真的變灰），在深色主題上一眼就看得出來。
- 四片互不重疊，永遠最多 4 片，不會疊黑。
- 洞比錨點放大 0.5px：`body{zoom}` 換算會留下 0.x px 的小數，不留餘裕的話遮罩邊緣會壓到被選中區的邊框上（實測量到 0.02～0.2px 的溢出）。

## 2. 「一些區被通知蓋住，對不起來」

這一項查下去發現有**三個不同的原因**疊在一起，全部修掉。

### 2-1（真正的根因）示範盤面自己動了 ── 第六期的「閒置 3 秒自動擲骰」

你的截圖裡說明卡停在「⑤ 盤面」，中欄卻是「要翻哪一堆機會？」。原本我推測是有 modal 卡住，
探針打下去**推翻了這個假設**（`pendingDecision: null`、`#center` 是空的）。

改用時間軸重測才抓到：

| 載入後 | 相位 | 中欄內容 |
|---|---|---|
| 0 秒 | ROLL | （空） |
| 2 秒 | ROLL | （空） |
| **5 秒** | **DECISION** | **「要翻哪一堆機會？你的現金 834,060 …」** |

原因在 `index.html:8310` 一帶：第六期做的「閒置 3 秒自動擲骰」（`autoRollSec`，預設 3）
對教學裡的示範局照樣生效。你看說明看超過 3 秒，示範局就自己擲下去、跳出選牌堆面板，
畫面整個換掉——高亮框當然就跟內容對不起來了。你截圖裡那顆鈕上寫的「擲骰（3）」就是倒數。

**修法**：示範局的設定檔強制 `cfg.autoRollSec = 0`，並在建好盤面後把殘留的計時器清掉。

### 2-2 toast 通知浮在解說區上面
`#toast` 是固定在畫面**正下方置中**（`bottom:100px`，z-index 820），正好壓在「⑨ 操作區」
和「⑧ 交易所」上。教學是靜態展示，不需要任何即時通知——`tut.boot()` 裡直接把 `ui.toast`
換成靜音版（訊息仍收進 `_mutedToasts`，不影響正式局的邏輯）。

### 2-3 錨點被捲到畫面外／導覽列與說明卡壓到被選中的區

- **內捲軸**：`html,body` 是 `overflow:hidden`，但左中右三欄各自有內捲軸（`#infoL`、`#infoM`、`#sheet`）。
  「⑮ 庫存股票」在 1440×900 下位於 y=914，**整塊在視窗外**，高亮框畫在看不見的地方。
  → 切步驟時先 `scrollIntoView({block:"nearest"})`；並用捕獲階段監聽所有捲動事件重畫
  （`position:fixed` 的框不會跟著內層捲動跑）。
- **導覽列**：焦點壓到底部那條帶時，導覽列自動移到畫面上方（`.tutBar.top`）。
- **說明卡**：改成「右→左→下→上」四個候選位置逐一試，只挑**完全不重疊焦點區、也不壓到導覽列**的位置；
  兩側都塞不下時把卡片縮成剩下的空檔寬度；真的無處可放（整面板類的第二層）才允許疊上去，並標記 `.over`。
- **第二層面板有進場動畫**：30ms 量到的是動畫中途的位置（實測「⑰ 記帳盤面」偏 8,23px），
  落定後 260ms 再對一次。

### 2-4 順手加的擋點層
示範盤面現在是**點不動的**（`#tutShield`，z-index 875）。沒有這層的話，你在教學裡點一下擲骰、
點一張卡，示範局就會真的往前跑，說明卡講的跟畫面看到的又會對不起來。
「⚠ 會害你輸的七件事」對話框改掛在 `#tutLayer` 內，才不會被擋點層吃掉點擊。

## 3. 自由點功能重做

### 原本
15 塊全部畫框＋圓點，**沒有任何說明**；點下去會直接跳離自由模式、切回一步一步的導覽。
等於「自由點」點了就沒有自由了。

### 現在
- **總覽**：15 塊細框＋編號圓點，畫面完全不遮罩、不壓暗——就是原本的盤面加上編號。
- **點編號**：那一區聚焦（金框＋四片遮罩把其餘翻灰），旁邊浮出說明卡，**仍然停在自由模式**，
  其他 14 顆圓點照樣可以點，可以一路點過去。
- **再點同一顆**：收起說明卡與遮罩，回到總覽。
- 導覽列文字跟著換：「自由模式——點編號看說明」／「點同一個編號可收起」。
- 「開始導覽」鈕仍在，隨時切回一步一步帶。

## 6. 未預期發現

1. **「閒置 3 秒自動擲骰」會污染任何靜態展示畫面**。這次是教學，但同一個機制對未來任何
   「示範／截圖／回放」用途都會有同樣問題。建議：之後若再做展示型畫面，一律先關 `autoRollSec`。
2. **`box-shadow` 撐大當遮罩在深色主題上等於沒有效果**。這是這次第 1 項的根因，
   不是視覺偏好問題——55% 的黑壓在本來就接近黑的底色上，肉眼分辨不出來。
   要「翻灰」就必須用 `grayscale`，不能只靠壓暗。
3. **我第一次的診斷假設是錯的**。我原本推測是 modal 卡住，探針打下去直接推翻（`pendingDecision: null`）。
   正確作法是改用時間軸重測——**單點快照看不到會隨時間變化的缺陷**。

# T-004 新股公告——電腦觸發時真人完全收不到跳卡

- 需求來源：製作人 2026-09-11 實機遊玩回報（v2.53.0-S45，單機對電腦局）
- 撰寫：architect，2026-09-11
- 嚴重度：Critical（製作人分級：整個 T-001 新股抽籤機制在「電腦觸發」這條路徑下，對真人玩家實務上等於不存在——玩家完全不知道發生過申購機會，也無從參與）
- 對應 ADR：`docs/adr/ADR-001-新股抽籤.md`（D5 節，2026-09-11 修訂）＋ 補充裁決 `docs/adr/ADR-001-新股抽籤-T004補充裁決.md`（**完整根因分析、驗證輸出、lockstep 風險評估、逐行修法都在這份文件，開工前必讀，讀完不需要再回來問 architect**）

## 1. 現象（製作人原話摘要）

單機對電腦局，第 14 輪出現「📢 新股申購開放」公告，但沒有任何選單跳出來讓他選，到第 15 輪直接結算成「0 筆申購，中籤 0 筆」。

## 2. 根因（architect 已用程式碼＋一次性驗證腳本確認，非猜測）

`E.openIpo`（`src/engine/reducer/applyAction.js`，目前約 4638-4650 行）目前只在觸發者是真人時才 `E.pushDecision` 推 `IPO_ANNOUNCE` 決策卡：
```js
if(!p.isNPC) E.pushDecision(S,p,{ kind:"IPO_ANNOUNCE", ipoId:id });
```
只要觸發者是電腦（踩到 MARKET 格，或保底邏輯輪到電腦玩家開盤），這一行完全不會執行，真人玩家這一局**收不到任何一張決策卡**，唯一剩下的是：
- 一則約 4 秒的被動 toast（`uiViews.js:391-393`）
- 交易所面板一個非阻塞的資訊列（`uiCore.js:932-948`）

這兩層通知在單機自動播放電腦回合的節奏下，實務上非常容易被忽略——這正是製作人回報現象的根因。architect 已用一次性腳本直接呼叫 `E.openIpo(S, npcPlayer)` 重現：`decisionQueue` 開盤後是空的（`[]`），證實真人這局完全收不到卡。

## 3. 修法（已裁決，直接照做）

見 `docs/adr/ADR-001-新股抽籤-T004補充裁決.md`「具體改法」段落，逐字採用即可。摘要：`E.openIpo` 最後一行從「只推給觸發者（且限真人）」改成「開盤當下同步推給全場還在場、沒破產的真人」，用 `S.players.forEach` 逐一 `E.pushDecision`，比照既有 `STOCK_GAIN`（`contentNpcSim.js:103-116`）的模式。**只改這一個函式**，不動 `E.ipoPollNPC`、`E.settleIpo`、`case "MARKET"`、`E.beginTurn` 保底區塊、D3/D4 帳本邏輯。

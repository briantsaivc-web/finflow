# FinFlow M8 S3 變更說明：過時、放棄、干擾、引擎修正
**版本**：v2.4.1-M8S2b → **v2.4.2-M8S3**　**日期**：2026-08-28
**基準檔**：`FinFlow_M8S2b_index.html`（已留備份 `FinFlow_M8S2b_index.html.backup.2026-08-28`）
**產出檔**：`FinFlow_M8S3_index.html`（912,718 bytes，md5 `a207e4aeb2836d1673f93e5512db00e6`）

## 1. 這一階在回答的問題

S1 讓玩家能「學」，S2 讓技能能「兌現」。S3 回答的是使用者原本的設計主張的後半段：

> 人生就是在做選擇跟為種下的因承受其後果；努力不一定有結果，但是不努力、不準備，機會來了就會錯失。

如果技能學了就永遠有效，遊戲就會退化成「開局全買就對了」。S3 讓技能會過時、學習會被打斷、準備會被時代作廢——但同時留一條回頭路（進修更新），讓玩家的選擇仍然有意義。

## 2. 改了什麼

### 2.1 三個新 op（Effects DSL）

| op | 語意 | 用在哪 |
|---|---|---|
| `DECAY_SKILL` | **先預告、後失效**。點名可過時的技能，寫入 `decayPendingUntil`，預告輪數（預設 2 輪）到期才真的 `decayed=true` | 產業變革 MACRO 卡 |
| `GRANT_SKILL` | 直接取得技能（不花時間）。已具備者不重複給、不重複計數 | 公司內訓 LIFE_EVENT |
| `DELAY_LEARNING` | 學習進度延後、`interrupted++`、學費不退 | 學習干擾 LIFE_EVENT |

三個 op 都做了「內容缺失不得炸」的防禦（找不到卡、沒在學習 → 安靜跳過，不產生 NaN、不憑空造出狀態）。

### 2.2 新內容 6 張

- **產業變革 MACRO 3 張**（`moduleReq:"M8"`）
  - `MAS01` 生成式 AI 全面進入開發流程 → `family:"TECH"`（程式與自動化）
  - `MAS02` 民法與稅法同步大修 → `SKL_LAW`
  - `MAS03` 技術士證照制度改制，舊證落日 → `SKL_PLUMB`
- **學習干擾 2 張**（`requiresLearning:true`，沒在學習就不會抽到）
  - `SKE_OT` 公司臨時接了急單，連兩週加班
  - `SKE_CAREGIVE` 家裡有人住院，你請假輪班照顧（另扣看護與交通 8）
- **公司內訓 1 張**：`SKE_INTRAIN`（`requiresNotSkill:"SKL_BOOK"`，已會就不會再抽到）

配合把 `SKL_LAW`、`SKL_PLUMB` 標記為 `decayable`（法規會修、證照會落日）；`SKL_CODE` S1 起已標。

### 2.3 進修更新流程（回頭路）

已過時的技能重學：**學費 ×0.5、輪數 ×0.5（無條件進位，至少 1 輪）**，學成後寫入 `refreshedAt`。
- 新函式 `E.skillIsRefresh(p, card)`、`E.skillTurns(S, p, card)`
- `E.skillPrice(S, card, passive, p)` 新增第 4 個參數；**不傳 `p` 時行為與 S2 逐位元一致**（向後相容，T-40 有專門斷言）
- 進修選單／技能卡面板／側欄都會標示「（更新）」「N 輪後過時」「已過時，可半價更新」

### 2.4 途徑 B：三處精準引擎修改

| 技能 | 修改點 | 效果 |
|---|---|---|
| 基礎水電 `SKL_PLUMB` | `E.opsRisk` | 房產修繕支出 **×0.5**。**只動金額、不動 RNG 呼叫順序**（T-42a 有專門斷言，否則會破壞重放） |
| 談判與溝通 `SKL_NEGO` | 新函式 `E.negotiatedPrice`，用於 `E.executeTrade` 與 `E.resolveOppAuction` | 買方成交價 **−10%**，賣方同額減收，**帳上金額守恆**。刻意不動 `npcAuctionBid` 的出價（那裡消耗 `randAux`），得標者不變 |
| 記帳與看財報 `SKL_BOOK` | `E.oppCompare(S, card, viewer)` | 揭露空租／修繕期望值與獲利波動，多出 `netIncome`／`netYield`／`riskNote`。**毛數字 `income`／`yield` 刻意不動**，沒技能的人不會被動享受到這份資訊。NPC 二選一也吃這份資訊 |

## 3. 鐵律遵循情況

**鐵律一（不得把 NaN／undefined 端到玩家面前）**：三個新 op 皆有缺內容／缺狀態的防禦；60 局 × 5 種模組組合模擬零例外、零 NaN。

**鐵律二（關閉開關必須與基線逐位元一致）**：
- M8 未啟用：12/12 局與 C2 基線完全一致
- `skillPerGame=0`：12/12 局與基線完全一致

**鐵律三（寫死的清單要一起改）**——這次找到第 5、第 6 處：
- `E.buildDecks` 的基礎 pool 過去只擋 `SKILL_GATE`，S3 的干擾卡／內訓卡會漏進來 → 加上 M8 總開關
- `MACRO_EVENT` 牌堆過去**完全沒過 `ok()` 濾網**（當時沒有帶 `moduleReq` 的總經卡）→ 補上 `moduleReq` 與 M8 總開關

第二點如果沒抓到，`skillPerGame=0` 的關閉開關會直接失效。

## 5. 未預期發現（不得靜默處理）

### 5.1 談判技能在模擬中從未生效——原因是模擬打不到那條路，不是程式壞了

60 局實戰中 `SKL_NEGO` 被學會 **65 人次**，但折讓金額為 **0**。追查結果：

```
拍賣開標 AUCTION_STARTED = 0 ／ 成交 AUCTION_RESULT = 0 ／ 轉讓成交 TRADE_DONE = 0
```

**拍賣與轉讓都是真人發起的動作**（`START_OPP_AUCTION`、掛牌轉讓），純 NPC 模擬永遠不會觸發。這正是先前記錄過的教訓「**NPC 不會走的路等於沒被測到**」再次應驗。

- **緩解**：T-42(b) 以直接單元測試覆蓋 `E.negotiatedPrice` + `E.executeTrade` 的完整路徑（含金額守恆斷言），並經反向驗證確認會在未修補版失敗。
- **仍未覆蓋**：真人在實際 UI 上走「掛牌拍賣 → 有技能的真人得標」的端到端流程。這需要真人實測，**AI 無法自驗**。建議實測時開一局多人、故意讓某人學談判後去搶標，看成交價是否為出價的 9 成。

### 5.2 修掉一個 S3 才會浮現的設計缺陷：過時技能會永久佔住 NPC 名額

第一輪驗收時「進修更新」只發生 2 次。追查發現 `npc.skillToLearn` 的 `npcSkillCap` 是用 `Object.keys(p.skills).length` 計算的——**已過時的技能仍佔一格**，NPC 一旦被產業變革掃到就再也不會回頭進修。改成只計算 `decayed=false` 的技能後，進修更新從 2 次上升到 12 次。回頭路才真的存在。

### 5.3 修掉「白付教材費」

內訓卡 `SKE_INTRAIN` 原本會重複抽到已具備 `SKL_BOOK` 的玩家身上——扣 3 但什麼也沒得到。加上 `requiresNotSkill` 閘；已過時時則可再度抽到（這本身就是一條回頭路）。

### 5.4 修補腳本的一次「靜默無效」

以 Python 就地改寫 `patch_m8_s3.py` 時，中途 `assert` 失敗使整支腳本在寫檔前中止，**四項修改全部沒有落地**，但 `patch_m8_s3.py` 仍能正常執行（跑的是舊內容）。與先前記錄的「`cat >>` 追加在寫檔語句之後而無效」屬同一類。已當場察覺並重跑，未污染產出；**教訓：改修補腳本後，必須從輸出檔實際抽查改動點是否存在，不能只看腳本執行成功**。本次已做（§4 落地抽查 13 個錨點全部命中）。

# FinFlow 變更說明 — M12-A 多人連線（各自裝置同局）v2.2.0

日期：2026-08-27　·　基底：v2.1.2　·　對應規格：《FinFlow M12 多人連線工程書 v1.0》（依你確認的開發路徑「單機→多人在一塊→多人可遠端」，把 Firebase 通道提前到第一期，讓 NB＋iPad 可以先玩）

## 這一期你會看到什麼

開局畫面多了「🌐 多人連線（各自用自己的裝置）」。點進去有五件事：

1. **建立房間**：選人數（2–6）與難度，產生 6 碼房號。真人不足的座位由電腦補位。
2. **加入房間**：輸入 6 碼房號 → 大廳改名、選職業與夢想 → 按「準備」→ 房主開局。
3. **重新連線上一局**：斷線、關頁面、換分頁後，一鍵追回進度、座位不變。
4. **同機測試（雙視窗）**：不用任何設定，同一台電腦開兩個視窗就能互連——你現在就可以自己先體驗整個流程。
5. **⚙ 連線設定**：跨裝置（NB＋iPad）需要先做一次 Firebase 設定（約 10 分鐘），步驟見隨附的《Firebase 設定指南》。**這一步要你本機操作，我這邊的環境連不到 Firebase，實機跨裝置的最終驗證要靠你的 NB＋iPad。**

## 遊戲中的多人體驗

- 別人的回合：你的中央區顯示「⏳ 等待 ○○○ 做決定中／記帳中／準備擲骰」，這段時間你可以看財報、規劃下一步；自己的回合照舊操作。
- 玩家列每個真人名字前有 🟢／🔴 在線燈（30 秒內有心跳算在線）。
- **資產轉讓已經是真人對真人**：你在交易所對另一位真人提案，對方的裝置會跳出回應視窗（接受／還價／拒絕）——勾心鬥角請面對面談，遊戲負責記結果。
- 拍賣、合資、P2P、轉介遇到真人對象：本期暫由系統自動評估意願（畫面上有標註），M12-B 開放真人親自出價與回應。
- 電腦玩家由房主裝置代跑，房主視窗要保持開著。
- 多人局鎖定：參數面板（btnDev）停用（決定論要求全員參數一致）；「結束遊戲」只有房主能按；版本不同的人會被擋在房外並提示重新整理。

## 技術上做了什麼（工程紀錄）

- **同步的不是狀態，是動作（lockstep）**：每個動作編號上鏈（seq 0,1,2,…），各端用同一顆種子重放同一串動作——引擎本來就是決定論事件溯源（T-01 鎖定），所以「重放必同局」。動作先在本機試跑、被拒就不上傳，紀錄裡永遠只有合法動作；兩人同時寫同一格會有一人吃到 conflict，補齊後提示「狀態已更新，請再操作一次」。
- **通道抽象（SyncAdapter）**：LocalAdapter（同瀏覽器雙視窗，BroadcastChannel＋localStorage）供測試與展示；FirebaseAdapter（Realtime Database，匿名登入，log 每格 transaction 寫入一次、規則層禁改）供跨裝置。入房時兩種通道自動嘗試，玩家不用管模式。
- **視角改造**：介面原本寫死「玩家＝0 號」；本期把 47 處寫死改為 ui.myId()（多人時＝你的座位），單機時仍為 0，行為不變。
- **重連**：讀回 setup → 同種子重建 → 靜音重放全部動作（不彈歷史提示）→「已同步至第 N 輪」。
- 開局流程重構為 buildGameConfig（參數組裝）＋ startCore（開局核心），單機與多人走同一條路。

## 未預期發現（依工作守則回報）

1. **同機雙視窗會撞成同一個人**：玩家身分原本存 localStorage，但同瀏覽器兩個視窗共用 localStorage，第二個視窗會頂掉第一個的座位。已改為 sessionStorage（每視窗一個身分），重連時再用 localStorage 記住的上一局身分認回座位。這正是「同機測試」模式能成立的關鍵修正。
2. **交易所按鈕殘留舊寫法**：灰化條件裡有一處 `x.id!==0` 漏改（多人時會把「自己」當成可交易對象、把 0 號排除），已改為 `ui.myId()`。
3. 規格草案裡 NPC 補位命名式有誤（重複人格加「②」的判斷寫錯），實作時已簡化修正。

## 建議的實測順序（配合你的 NB＋iPad）

1. 先不設定任何東西：NB 上開兩個視窗 →「同機測試（雙視窗）」跑一局，感受流程（5 分鐘）。
2. 照《Firebase 設定指南》做一次性設定（10 分鐘），金鑰貼進 NB 和 iPad 兩台。
3. 把 v2.2.0 的 index.html 拖上 Netlify → NB 建房、iPad 輸房號 → 開打。
4. 途中故意把 iPad 切到別的 App 再切回來、或關掉 Safari 重開 →「重新連線上一局」→ 看是否追上（這就是驗收 8、9）。

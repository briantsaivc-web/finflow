## 4. 輪盤改成規整的方格環（照提案）

原本 `ui.rectPos` 是「沿矩形周長平均分佈」，格子會落在不整齊的位置、四角特別擠，跟提案的樣子差很多。

改成 **格子網格環** `ui.ringGeom(n, box, aspect)`：把 n 格排成 `cols × rows` 的框（沿邊順時針），每格等大、間距一致。

- 內圈 24 格 → **9 × 5**（`2×9 + 2×5 − 4 = 24`）
- 夢想圈 12 格 → **6 × 2**（就是上下兩排）
- viewBox 從 `520×700` 改成 `520×405`——比例更接近容器，盤面實際變大
- 中央放「底層牛馬區 ／ 被動收入蓋過支出才走得出去」，擲骰與結束回合的按鈕浮在它下方
- 棋子改坐在格子上緣（夢想圈坐下緣），依同格人數自動縮小，不再蓋住格子名稱

**格子索引、內容、移動邏輯完全沒動**，只換了畫法。

## 6. 結束遊戲按鈕降級

原本是金色漸層的 `primary`，跟「主要行動」長得一樣，但它是低頻且不可逆的操作。改成 `.act.quiet`：透明底、灰字、細框；滑鼠移上去才轉紅。

## 7. 人生商城反灰調亮

原本 `opacity:.4 + grayscale(1)`，買不到的商品幾乎讀不出在賣什麼。改成 **只降對比、不去彩度**：`opacity:.82`、虛線框、標題與價格各自保留可讀的顏色，圖示只降一半彩度。「看得清楚在賣什麼」跟「現在買不了」同時成立。

## 8. 自動記帳六套依實際出現頻率排序

跑了 **900 局模擬**（3 組模組／陣容），統計會出記帳題的分錄共 **56,813 筆**：

| 排序 | 類型 | 整筆出現 | 題目數占比 |
|---|---|---|---|
| 1 | **現金買資產** | **51.8%** | 54.3% |
| 2 | **消費與誘惑** | **18.4%** | 10.7% |
| 3 | **資產變現** | **12.1%** | 10.5% |
| 4 | **收入類** | **9.1%** | 6.5% |
| 5 | **貸款買資產** | **7.3%** | **16.9%** |
| 6 | **借款與償債** | **1.3%** | 1.2% |

排序依據用的是**整筆出現的頻率**，因為「連續 5 次整筆全對」才解鎖那一套——決定你多快能脫離手記的是整筆次數，不是題目數。

**一個值得注意的落差**：貸款買資產整筆只占 7.3%，但每次會出到 4 格，題目數占 16.9%——屬於「少見但每次很重」。UI 上這一列直接標「少見但每次題目最多」。

每一列現在都寫出「這一套多常遇到（約 N% 的帳）」，玩家自己看得出先練哪一套划算。

> **這份統計的限制**：資料來自 NPC 對局。NPC 的買賣行為跟真人不完全一樣，尤其 NPC 很少主動提前還款（所以「借款與償債」可能被低估）。真人實測後如果體感差很多，這個排序可以再調——順序寫在 `E.BK_GROUPS` 的陣列裡，改順序就好。

## 9. 非回合動作開放（**有數值影響**）

依你的裁決：**只放行不影響別人的動作**。

| 動作 | 非回合 | 理由 |
|---|---|---|
| 提前還本 REPAY_LOAN | ✅ 放行 | 只動自己的現金與負債 |
| 定期定額 SET_DCA | ✅ 放行 | 是設定，發薪日才執行 |
| 股息再投入 SET_DIV_REINVEST | ✅ 放行 | 同上 |
| 逛商城買東西 MALL_BUY | ✅ 放行 | 只動自己；每輪額度不變 |
| 買賣資產／股票 | ❌ 維持回合限定 | 會動到市場與部位 |
| 借款 TAKE_LOAN | ❌ 維持回合限定 | 會改變信用與槓桿結構 |
| 轉介／合資／P2P／拍賣 | ❌ 維持回合限定 | 要別人回應 |

### 順手補掉一顆沒爆的地雷

`E.apply` 裡的 `var p = E.activePlayer(S)` —— **p 一直都是「當前輪到的玩家」，不是送出動作的人**。舊碼所有 case 都直接用 `p`，所以非當前玩家送進來的動作會變成「幫當前玩家操作」（例如幫別人還款、幫別人借錢）。原本只靠 UI 與 `mpMayAct` 擋住，引擎層沒有任何防線。

這一版把它變成引擎規則：

```js
var actor = S.players[action.playerId] !== undefined ? S.players[action.playerId] : p;
var OFF_TURN_SELF    = { REPAY_LOAN, SET_DCA, SET_DIV_REINVEST, MALL_BUY };
var OFF_TURN_RESPOND = { RESPOND_TRADE, RESPOND_REFERRAL, RESPOND_P2P, RESPOND_JV,
                         PLACE_BID, PROPOSE_P2P, TOP_UP_MARGIN,
                         PLAYER_LEAVE, PLAYER_RETURN, END_GAME, CONFIG_PATCH, CLEAR_TRADE };
if(!isMyTurnAction && !OFF_TURN_SELF[type] && !OFF_TURN_RESPOND[type]) return reject("NOT_YOUR_TURN");
```

四種放行的動作全部改成指向 `actor`，不再用 `p`。T-85 直接驗這件事：非回合還款後，**當前輪到的那個人的現金與負債必須一格都沒動**。

### 非回合的帳，輪到自己時仍然要記

記帳題本來只掃「本輪」的分錄，非回合做的帳會整批漏掉——尤其「借款與償債」本來就是最少見的一套（1.3%），漏掉就永遠練不熟。

處理方式：非回合產生的分錄標記 `offTurn`，`buildBookkeeping` 會把它們一起撈進來出題；整筆處理完（答對或答錯都算）就清掉標記，不會一直重複問。

### 10.2 非回合動作：模擬測不到，必須真人實測
上面那個 0/500 同時說明另一件事：**NPC 從來不會在別人的回合做動作**，所以這項改動在模擬裡完全看不出來。它的實際影響只會出現在真人局：

- **提前還本可以提早幾個回合** → 少付一點利息（影響很小但非零）
- **商城購買時機更自由**（每輪額度仍是 1 項，總次數不變）

**我沒有辦法用模擬給你這項的平衡數字。** 要看真實影響，只能三個人實際打一局，比對「大家的還款時點是不是明顯提前」。

## 1. 記帳自動化：四象限 → 六套交易類型

依你的說法「一套一套的自動化，不是四種分開看」。

### 六套

| 套 | 帳的組成 | 這一套在教什麼 |
|---|---|---|
| **現金買資產** | 資產＋現金 | 錢變成東西：現金減少、資產增加，淨值不變 |
| **貸款買資產** | 資產＋負債＋支出 | 借錢買的東西：資產與負債同時長大，還多一筆利息支出 |
| **資產變現** | 資產＋現金＋收入 | 賣掉東西：資產減少、現金增加，那筆收入也跟著停 |
| **借款與償債** | 負債＋現金＋支出 | 純粹的錢與債：沒有東西進出，只有負債水位在動 |
| **消費與誘惑** | 支出＋現金 | 花掉就沒了：不會留下任何可以再賺錢的東西 |
| **收入類** | 收入＋現金 | 錢進來：分清楚是靠時間換的，還是資產自己長的 |

分套的依據是**這筆分錄長什麼樣**（`E.bkGroupOf` 看 postings 的組合與資產增減方向），不是卡片來源——因為玩家要練的是「這一組帳怎麼記」，而同一種帳會來自很多張不同的卡。歸不到任何一套的分錄照樣要作答，只是不計入熟練度。

### 「整筆全對」才算一次

這是這一版最重要的一條規則：**同一筆帳要整組分對才算一次，錯一格整筆重來**。連續 5 次整筆全對才解鎖那一套。理由是半套會的人不該拿到自動化——貸款買資產的重點就在「資產、負債、利息三個一起動」，只認得其中一格不算會。

解鎖之後該套的帳**整筆**不再出題（不是只跳過某幾格），開不開仍由玩家決定，隨時可改回手記。練熟時只跳一個提示，不打斷、不強迫選擇。

`SET_BK_AUTO` 改收 `group`；舊的 `quadrant` 呼叫會被拒（T-64 已改成遷移守門，確認兩套不並存）。

## 2. 數位資產：三個旋鈕一起轉

依你的裁示三項全做。

| 參數 | S12 | S13 |
|---|---|---|
| 基礎收入倍率（新增 `digitalIncomeMult`） | — | **1.8×** |
| 爆紅倍數 `digitalHitMult` | 3 | **4.5** |
| 本行做白工 `digitalFlopPct` | 45% | **33%** |
| 外行做白工 `digitalAmateurFlopPct` | 60% | **50%** |
| 本行爆紅 `digitalHitPct` | 15% | **18%** |
| 同時可經營（新增 `digitalConcurrent`） | 1 | **3** |

**「同時可經營多個」放寬的是「開得了幾攤」，不是「不用顧」**——`p.tending` 一次仍然只能顧一個，顧不到的照樣爬不動、照樣衰減。攤數滿了就不再抽到新的數位資產卡（否則只會每一攤都顧不到）。

### 效果量測

```
長尾收入合計（60 局 / 180 人次）：487 → 1333
每人次長尾收入（24 局同種子直接對照）：2.70 → 5.56
```

同一組種子，把三個旋鈕轉回 S12 的值再跑一次比出來的，不是換了量測方式。

**沒有變成免費午餐**：做白工仍是最常見的結果（本行 33% vs 爆紅 18%、外行 50% vs 5%），外行仍然每個維度都比本行差。平衡對照四項區間全部重疊。

## 3. 抽到數位資產卡時可以放棄進修來接

依你的說法「技能隨時可以重修，發展特殊技能是要抽中才有」。

`START_DIGITAL` 新增 `dropStudy` 選項，**沿用既有的 `ABANDON_SKILL`**，不另做一套。卡面把代價當著玩家的面攤開：

> **放棄進修，接這個**
> 中斷「基礎水電」（已投入 3 輪、學費 21，退回 6.3、沉沒 14.7），再投入 18 開始經營
>
> 技能隨時可以重修，這張卡錯過就沒了——但沉沒的學費不會回來。「該不該停損既有投入去換更好的機會」，本身就是一道題。

進修中直接按「開始經營」仍然不行（避免繞過取捨）；沒在進修時選 `dropStudy` 不產生任何作用；退費後現金仍不足則開不成。

## 5. 未預期發現：兩個守門的職責被我測混了

第一輪反向驗證時，前兩項（不要求整筆全對／答錯不作廢）**都沒被抓到**。查下去發現我把兩個機制寫在同一個情境裡驗，而它們互相蓋住：

- `restT`（該筆還有未答完的題就不計分）擋的是「**只答了一部分**」
- `bkEntryBad`（整筆作廢）只在「**答錯之後又把同一格改對**」時才會用到——因為答錯的那一格會保持未答，`restT` 自己就擋住了

我原本只寫了「錯一格 → 歸零」一個情境，那個情境同時被兩個守門蓋住，等於兩個都沒驗到。改成四個情境各自對準一個之後才驗得到：

1. 三格全對但只答一格 → 不得計分（守 `restT`）
2. 三格全部答完且全對 → 恰好 +1，不是每格 +1
3. 中間錯一格沒補答 → 不算
4. 錯一格之後補答正確 → **整筆仍然作廢**（守 `bkEntryBad`）

這是本專案第四次遇到「測試通過但沒驗到東西」，前三次是條件式跳過（S10）、前置狀態剛好為空（S11）、樣本被別的規則擋住（S12）。這次是新的一種：**一個情境同時滿足多個守門，於是每個守門都沒有被單獨驗證**。做法補上：一個機制配一個情境，而且每個情境都先 `assert` 前置條件成立。

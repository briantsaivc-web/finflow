## 1. 你提的兩件事

### 1.1 每張決策卡都看得到現金

不是逐張卡去補，而是在 `ui.decisionCard`（所有決策面板的唯一入口）頂端掛一條狀態列：

> 💰 現金 **1,234**　月結餘 **+56**　每月支出 **78**

這樣任何現在有的、以後新增的決策卡都自動有。`PICK_OPP` 與 `CHOOSE_DECK` 本來就有更完整的現金說明，不重複顯示。

### 1.2 股價漲跌改成「與上一期比較」

**你抓到的是一個資訊洩漏。** 原本的漲跌% 是用**面額**當基準（`(price − face) / face`），而價格下限是 `face × stockFloorMult`——所以看到 −90% 就等於知道離地板不遠了，玩家可以據此推測底部。

改成 `E.stockChange(S, def)`：以**上一期收盤**為基準，顯示「▼10%（較上期）」。期間變化不帶任何關於地板位置的資訊。持股者自己的損益仍以成本價計算（那是他自己的資訊，不洩漏牌面）。

## 2. 新功能：數位資產（第四類資產）

規格書 §2.5 的「混合起飛」模型：**累積決定會不會起來，機率決定起多高。**

### 2.1 怎麼運作

| 階段 | 機制 |
|---|---|
| **開張** | 抽到數位資產卡（**必須先具備對應技能**，否則卡片根本不會出現）→ 扣建置成本、每月維護費進支出水位 |
| **爬坡** | 每輪要**投入時間**才會 +1 進度；沒投入就原地不動（不倒退，但也不會自己長大） |
| **起飛** | 累積達門檻 → 擲一次骰：**FLOP 45%**（×0.3）／**OK 40%**（×1.0）／**HIT 15%**（×3.0），並鏡射一筆到 `p.assets`，被動收入才吃得到 |
| **停更** | 每輪 ×0.85 衰減，跌破起飛值的 15% 就歸零、從 `p.assets` 下架、維護費一併停止 |
| **回來** | 重新投入會止跌並以 ×1.06 慢慢回升，上限是當初的起飛值——回得來，但比當初慢得多 |

**時間是唯一真正稀缺的東西**：一次只能經營一個，而且**進修中不能經營**（開始學習會自動放掉時間槽，爬坡停在原地、已起飛的開始衰減）。

**與副業的關鍵差別**：辭職圓夢時，副業的收入與成本一起消失；數位資產只停維護費，**長尾收入保留**——做出來的東西會繼續替你賺錢。這正是它值得投入的理由。

### 2.2 內容

5 張，各需一項對應技能：線上課程（記帳）／YouTube 自己動手修（水電）／圖庫與攝影課（攝影）／自動化工具訂閱（程式）／西語 Podcast（西語）。

`eduNote` 都指向同一課：**長尾屬於持續的人，不屬於做過的人。**

## 3. 順手抓到並修掉的缺陷：**S4 埋的存檔炸彈**

驗收時 T-36（重放一致性）突然不過。追下去發現不是 S5 的問題：

**`ui.save` 存的是 `p.professionId`，但 S4 的「轉職」會把它改掉。** 存檔存的是轉職**後**的職業，重放時卻拿它當**開局**職業 → 整局從第一輪就走偏。

影響範圍：**單機存檔讀取、多人連線 lockstep 全都會壞**（這個遊戲的存檔就是 actionLog 重放）。

實測失敗率（以 S4 自己的存檔重建方式跑）：

| 模組組合 | S4 | S5（修正後） |
|---|---|---|
| M1,M2,M4,M6,M8 | **1/40 失敗** | 0/40 ✓ |
| 全模組（含 M3） | **4/40 失敗** | 0/40 ✓ |

**修法**：新增 `p.initialProfessionId`（開局職業，整局不變），以及 `ns.seedPlayers(S)`——存檔與測試共用的**單一**開局資料定義，避免兩邊各寫一份而漂移。`ui.save` 改用它。

### 為什麼這個缺陷躲過了前面所有驗收

**我的驗證方法有洞。** `verify_*.js` 的「決定性重放」測的是 `playOne` 跑兩次結果相同——那只驗了 RNG 決定性，**根本沒碰到 `ns.replay`**。真正的 actionLog 重放只有 T-36 一個 seed 在測，剛好沒觸發轉職。

已補上：**`verify_s5.js` 新增「actionLog 重放沙盤」——40 局 × 2 種模組組合，逐步比對是否被拒、終局是否一致**，從此變成每期常態掃描。T-54 也專門針對這個缺陷類別：斷言「存檔種子只能放開局就決定、整局不變的欄位」。

### 4.1 自測 54／54 通過（新增 T-51 ~ T-54）

| 測試 | 內容 |
|---|---|
| T-51 | 股價以上一期為基準（−10% 而非相對面額 −55%）；歷史不足與缺欄位皆安全 |

## 5. 已知限制（誠實陳述）

**數位資產在模擬中偏稀有**：60 局 180 人次只開張 14 個（7.8%），因為電腦玩家要先學到對應技能、又要抽到那張卡。**「歸零下架」這條路在實戰模擬中一次都沒走完**（衰減 32 次但沒有死透），只有 T-52 的直接單元測試覆蓋到。

這是「NPC 走不到的路等於沒被測到」的老問題。真人玩家因為會主動選擇，觸發率應該高得多——但**這需要你實測才知道**。

## 6. 新增設定參數

| 參數 | 預設 | 說明 |
|---|---|---|
| `digitalPerGame` | 3 | 每局數位資產卡張數；0 為關閉整個系統 |
| `digitalFlopPct` / `digitalHitPct` | 0.45 / 0.15 | 起飛時三種結果的機率（其餘為 OK） |
| `digitalFlopMult` / `digitalHitMult` | 0.3 / 3 | 對應的收入倍數 |
| `digitalDecayRate` | 0.85 | 停更每輪衰減率 |
| `digitalRecoverRate` | 1.06 | 重新經營的回升率 |
| `digitalDeadPct` | 0.15 | 低於起飛值的這個比例就徹底歸零 |

## 7. 仍需真人實測（AI 無法自驗）

1. 決策卡頂端的現金列會不會太搶眼／擋到卡面
2. 股價「較上期」的百分比對玩家是否比原本的「相對面額」更有用
3. 數位資產的爬坡體感——4~6 輪的等待會不會太久而讓人放棄
4. 起飛揭曉（🌱／📈／🚀 三種演出）的滿足感
5. 「進修中不能經營」這個取捨玩家能不能理解，還是會覺得被綁手綁腳

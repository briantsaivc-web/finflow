## 1. 期貨有自己的報價（第 3 項）

在此之前期貨價**就是**現貨價，這其實不對——現實中期貨相對現貨永遠帶著基差。

```
期貨報價 = 現貨價 × (1 + 基差)      基差每輪重抽，範圍 ±futBasisMax（預設 0.01）
一口合約值 = 期貨報價 × 乘數        （原本用現貨價算，已改）
```

- 基差存在 `S.futBasis[symbol]`，由 `E.rollFutBasis` 在 `tickFutures` 的**最前面**抽一次（結算前），整輪固定。
- 逐輪損益改以**期貨報價差**計算：所以現貨一動也不動、光是基差從 −0.8% 收斂到 +0.6%，多單也會有損益。這是期貨獨有的一層風險，`s23btest` 有一項專門驗它。
- 看板那一列寫「期貨 ×10　56,730　溢價 0.8%　持 2 口」；期貨區與買賣面板的合約值全部改讀 `E.futContractValue`（同一個入口）。

### ⚠️ 這裡踩到一個決定論的坑
第一版把基差寫成「讀的時候發現沒有就抽一個」的 lazy 初始化。介面每次重繪都會呼叫 `E.futBasis`，於是**玩家看了幾次畫面**會改變 `util.rand(S)` 的消耗次數，亂數序列偏掉——重放測試在第 2 輪就與原局分歧。

已改成 `E.futBasis` 是**純讀取**（沒抽過就回 0），抽基差只在 `tickFutures` 裡做。並補一項測試：連讀 20 次 `futBasis／futPrice／futContractValue`，`S.rngState` 必須完全不變。

## 2. 自動補繳（第 5 項）

`futAutoTopUp`（預設 1）。逐輪結算後保證金掉到維持線以下時，順序是：

1. 現金補得起 **原始保證金** → 補到原始保證金；
2. 補不起原始、但補得起 **維持水位** → 補到維持水位（先讓部位活著）；
3. 兩個都補不起 → `E.futForceClose` 強制平倉，穿價轉信貸（沿用 S23b）。

補繳會排一張告知卡，寫明「本輪自動從現金補繳 X——**錢是真的出去了**」，並計入 `stats.futAutoTopUp`。自動補繳**不產生負債**（那是強平穿價才有的事）。

實測：ETF 逆向 25% 時，一口空單自動補繳花掉 393.8 現金，部位保住；現金抽乾後再逆向到 60%，才走強平並留下一筆「期貨穿價」信貸。

## 3. 口數上限與平倉鈕（第 1、2 項）

`futMaxLots_A/B/C` 5/3/1 → **10/6/3**。上限仍由 `E.futMaxLots` 一個入口決定，介面拉桿與引擎 `FUT_LOT_LIMIT` 讀同一個值。
平倉鈕改用 `class="opt primary"` ＋ `background:var(--neg)` ＋ `font-weight:700`，庫存區與期貨區都是同一顆。

## 4. 庫存與資產表（第 4 項）

- 庫存新增「⚡ 期貨」區塊：標的、方向、口數、進場價、保證金餘額、維持線、維持率（追繳中標紅）、平倉鈕。
- 資產表原本把期貨併進「非股票」那一列，改成獨立列「⚡ 期貨保證金」（`nonStock` 已排除 `FUTURES`）。仍不計入被動收入。

## 5. 未預期發現：期貨的通知卡會把整局卡死

**症狀（尚未在真人局出現，是做第 5 項時讀 code 發現的）**：`E.futForceClose` 與自動補繳原本直接 `E.pushDecision` 推 ACK 卡。但這兩者都跑在 `tickFutures` 裡，而 `tickFutures` 掛在 **`M9.onRoundEnd`**——**回合結束**。

引擎的不變式是「**待決策一定屬於當前玩家**」。回合結束時的當前玩家不一定是那個部位的主人：如果強平的是 3 號玩家，卡卻推在 1 號玩家的回合結束，1 號擲不了骰也結束不了回合，**整局死當**。這正是 S15d 踩過的同一個洞。

**為什麼所有既有測試都抓不到**：`npcUsesM9: 0`，NPC 從來不開期貨部位，所以 1000 局閘門與 400 局 M9 閘門裡根本沒有「別人的部位在你的回合結束時被強平」這個情境。這個洞只有真人多人局會踩到。

**修法**：新增 `E.queueFutNotice(p, notice)`，回合結束時只**排隊**（上限 4 張，避免無限長），存在 `p.pendingFutNotices`；等輪到他自己時由 `E.beginTurn → E.tickFutCall` 一次倒出來推成決策卡。破產的玩家直接清空不推（不能讓已經出局的人再被卡住）。

已補一項專門的不變式測試：把當前玩家換成別人再觸發強平，斷言 `S.decisionQueue` 必須是空的、`pendingFutNotices` 有 1 張、倒出後清空、佇列有上限、破產者不推卡。

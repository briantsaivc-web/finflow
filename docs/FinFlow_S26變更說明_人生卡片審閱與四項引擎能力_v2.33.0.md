# FinFlow S26 變更說明——人生卡片逐張審閱＋四項引擎能力＋卡片工坊改到能用（v2.33.0-S26）

這批的起點是一次逐張審閱：把 `LIFE_EVENT` 牌堆 34 張卡一張一張攤開來看「卡面寫什麼／教育意義是什麼／後果是什麼／強制還是可選／有什麼限制」，一張一張跟 Brian 對過。審閱過程中有些要求靠改文案就能解決，有些一碰就發現引擎根本沒有那個能力——後者沒有硬塞進卡片資料，而是拆成四項引擎能力先做出來，卡片再用它們。

主軸是 Brian 定的一句話：**「我們強調擬真與教育性，所以邏輯性很重要，調數值是下一步。」** 所以這批處理的都是「規則說不通」的地方（車禍賠償被醫療險理賠、戒掉貴習慣不管月薪高低都省一樣多、認真投資健康卻點不亮健康折抵），數值本身留給之後跑模擬再調。

## 一、逐張審閱改了什麼（內容層）

### 1.1 文案

`LE01` 家裡多了一個人／`LE02` 年度調薪／`LE07` 被挖角跳槽／`LE10` 三寶出生（改標題「增產報國，三寶出生」）／`SI_PIVOT`／`SI_SKILL`／`SI_NEGO`／`SI_SIDE`／`SI_AUTO`／`LE14` 寵物急診／`LE15` 交往對象出現了——都是 Brian 逐張口述的新文案。

`SI_NEGO` 這張中途改過一次方向：原本要用「會吵的孩子有糖吃」，查職業表後發現 20 個職業裡有 3 個（`PRO_PLUMBER` 水電自營、`PRO_FOOD` 小吃店老闆、`PRO_FOUNDER` 新創創辦人，`employmentType` 分別是 `SELF`／`SELF`／`FOUNDER`）根本沒有老闆可以談加薪，所以最終文案改成不指名對象的「你不爭取，沒人會主動幫你加薪」。**依身分切換卡片文案**（比照現有 `E.LAYOFF_FLAVOR` 的做法）這件事本身沒做，記在第七節待辦。

### 1.2 效果與規則

- **`LE01`／`LE06`／`LE10` 三張生小孩的卡**：各加「長輩紅包 +30」與「幸福感 +3」。三張給一樣的數字，不做邊際遞減——遞減在玩家眼中讀起來會變成「你家老二比較不值得高興」，那不是這個遊戲想表達的事；「養育成本不會因為第幾胎而打折」這個財務教育點，`ADD_CHILD` 本來就會依職業的 `perChildExpense` 自動加每月支出，已經在教了。
- **`LE07` 被挖角跳槽**：`SALARY_MULT` 1.15 → **1.5**。這是全牌堆最大的一次免費永久加薪（強制抽到、不用花錢），比要花錢的 `SI_MBA`（+28%）與職業表裡考照跳級（+40%）都大，Brian 知情後確認保留。
- **`LE04` 急性盲腸炎**：補上 `insurable`／`medical` 標籤。這張是整副牌裡最典型的「需要現金的醫療情境」，但原本沒標，導致玩家買了醫療險對它完全沒用——同副牌的 `LE09`／`LE11`／`LE12`／`LE13` 都標了，只有它漏掉。
- **`LE09`／`LE11`**：選項文字寫著「幸福感上升」但 `effects` 裡根本沒有 `GRANT_JOY`，玩家會看到說明與自動效果摘要對不起來。補上 `GRANT_JOY +1`。
- **`LE15` 交往對象出現了**：認真交往補 `GRANT_JOY +2`。
- **`EVT_GRAD_TRIP_PARIS_BALI` 一生一次的畢業旅行**：補 `oncePerLife: true`。標題寫「一生一次」，機制上卻沒鎖，同一局可以重複抽到。
- **`SI_HEALTH`**：每月省下 4 → **5**。
- **`SI_MBA`**：改成「公司補助八成」的敘事，玩家自付 60 → **200**（現實 20 萬 ÷ 千元制）。

### 1.3 車禍那兩張：醫療與修車拆開，各折各的

原本 `LE12`（開車擦撞）與 `LE13`（騎車犁田）各自只有一筆 `CASH_DELTA`，把醫療費與修車費混在一個數字裡。加上產險理賠之後就會出現一筆金額被三條折扣鏈連續打折的荒謬結果（產險 50% → 健康 30% → 醫療險 60%，−18 只剩 −2.5）。

改成兩筆效果，各走各的鏈：

| 卡 | 效果一 | 效果二 |
|---|---|---|
| `LE12` 開車擦撞 | 自己的車進廠維修 −12（`propertyClaim`：產險理賠 50%） | 對方求償與和解金 −16（`legalClaim`：法律技能折抵 50%） |
| `LE13` 騎車犁田 | 手臂擦傷的醫療自付 −10（走 `insurable` 的健康折抵＋醫療險） | 機車進廠維修 −8（`propertyClaim` ＋ `legalClaim`） |

`LE12` 同時**移除了 `insurable` 標籤**——這張卡沒有人受傷，是純財損與責任賠償，醫療＋意外險本來就不該理賠。這是本批唯一一項「拿掉既有機制」的改動，特別標出來。

### 1.4 產險改名，不是新開機制

原本要為車禍另外做一套車險機制，Brian 指出「住宅、地震、車子都是產險」，這是對的——現實中它們本來就是同一類保險商品。所以 `ML_INS2` 從「住宅火險＋地震基本保險」改名為 **「產險（住宅＋地震＋車險）」**，文案與 `payload.note` 一併更新，機制沿用既有的 `propertyClaim`／`propertyClaimPct`，**沒有新增任何引擎程式碼**。原本規劃的「新增車險機制」需求就此撤銷。

### 1.5 安太座、以及撞號的那批童年支出卡

- `ML_VIR5` 安太座：文案原本是「廟公貼上紅紙…」，Brian 說這張要的是日常好玩的說法、跟宗教無關，改為「定期把太座哄開心，比什麼都保平安。Happy wife, happy life.」，只留這一份。
- 更早一輪對話裡設計過一批童年支出卡（`LS21`～`LS25`），後來查 repo 才發現這批 id 已經被真實存在的卡佔用，且內容不同。依「明顯相同的合併、其他重編」處理：
  - 社團慶功宴＝現有 `LS21`、暑假夏令營＝現有 `LS24`、才藝表演比賽已被現有 `LS23`（孩子樂器採購與才藝比賽）涵蓋、小孩牙齒矯正＝現有 `ML_HEA3` → **四張合併，不新增**
  - 畢業典禮治裝、孩子的生日派對 → 現有卡沒有涵蓋，**重編為 `LS26`／`LS27`**

## 二、引擎能力①：`SET_FLAG`——卡片也能點亮旗標

原本「點亮玩家旗標」這件事只有人生商城購買那條路徑做得到（`applyAction.js` 裡讀 `it.payload` 的那一大段）。結果就是：「認真投資健康」這張卡明明在講運動與健檢，卻點不亮健康折抵；「公司送你去念 MBA」也解鎖不了人脈。

`engineCore.js` 的 `applyEffects` 新增 `SET_FLAG`：

- 永久型：`{"op":"SET_FLAG","flag":"network"}` → `p.flags.network = true`
- 期限型：`{"op":"SET_FLAG","flag":"fit","turns":24}` → `p.flags.fitUntil = 目前輪次+24`，只延長不縮短

期限型**刻意不寫 `<flag>Item`**：那是商城年約用來記「到期要問你要不要續約、月費該停了」的欄位，自我投資不是年約、沒有月費，也不該跳續約詢問。既有的到期迴圈（`["fit","checked"].forEach`）查不到 `Item` 時本來就會安靜略過，所以不需要為此改任何既有程式碼。

落地：`SI_MBA` 投資自己 → 解鎖特殊機會牌堆（與商城的 `ML_EDU4`／`ML_EDU6` 同一個 `network` 旗標）；`SI_HEALTH` 投資自己 → 24 輪健康折抵。

## 三、引擎能力②：依月薪計價

「戒掉昂貴習慣」對月薪 3 萬和月薪 30 萬的人是同一個固定數字，這在一個講擬真的財商遊戲裡說不通。`E.mallCost` 早就有 `costSalaryMult`（S21c 為安太座做的），但只服務商城購買；`SELF_INVEST` 的成本是直接讀 `sop.cost` 的固定值。

這批把同一套語意抽成兩個共用函式：

- `E.optionCost(S,p,op)`：`costSalaryMult` 存在且有薪水時回「月薪 × 倍數」，否則回 `op.cost`
- `E.effAmount(t,ef)`：效果金額支援 `salaryMult`（負數＝每月省下），沒薪水時回 `ef.amount`

回退規則跟商城一致：**沒有薪水（自由圈／失業）就用寫死的值**，不能讓沒收入的人反而付最貴。三處呼叫點都改了：引擎（`SELF_INVEST`／`CHOICE` 的成本檢查）、電腦玩家（`contentNpcSim` 的決策）、介面（按鈕上的金額與「現金不足」判斷）。

落地兩張卡（比例由 Brian 定，回本期是設計出來的，不是算出來的巧合）：

| 卡 | 一次性成本 | 每月省下 | 回本 | 沒薪水時的回退值 |
|---|---|---|---|---|
| `SI_QUIT` 戒除昂貴習慣 | 月薪 × 1.2 | 月薪 × 5% | 24 輪 | 48／每月 −2 |
| `SI_MOVE` 搬到房租更合理的地方 | 月薪 × 0.3 | 月薪 × 2.5% | 12 輪 | 12／每月 −1 |

## 四、引擎能力③：法律技能折抵

`SKL_LAW`（法律常識）與 `SKL_GOV_LEGAL`（公司法規與合規治理）原本在整個引擎裡只有一個實際用途——獨立董事的法律責任保護，外加卡面上一句吸金盤警語。這批讓它在「賠償／和解類支出」上真的有用：`E.legalDiscount` 的形狀比照 `E.healthDiscount`，折抵比例走新增的設定參數 `legalSkillDiscountPct`（預設 **0.5**，Brian 說先用 50%、跑模擬要調再調）。

觸發條件掛在**單一效果**的 `legalClaim` 旗標上，不是整張卡的標籤——正是為了第 1.3 節那個拆分：同一張卡的醫療費不會跟著被法律技能打折。

## 五、引擎能力④：選項層級的先修技能

原本 `requiresSkill` 只能掛在整張卡上（`kind:"SKILL"` 的階梯技能用）。Brian 要的是「卡照抽，但其中一個選項要有財務技能才選得動」，用意是給玩家一個去學技能的誘因。

- 引擎：`E.optionLocked(S,p,op)`，`SELF_INVEST` 與 `CHOICE` 的 `DECIDE` 都會擋
- 介面：`ui.decisionOptBtn` 統一產生按鈕，鎖住的選項**顯示出來但按不下去**，並標「🔑 先修：「記帳與看財報」（尚未學會）」。藏起來玩家根本不知道有這條路，就談不上誘因
- 電腦玩家：不會去選鎖住的選項（否則引擎擋下來，等於白白空過一次決策）

**交叉影響檢查抓到一個坑**：`SKL_BOOK` 掛在 M8 模組底下，沒開 M8 的局根本學不到，照鎖會讓 `SI_DEBT` 永遠只剩「暫時不」可選、變成一張廢卡。所以 `E.optionLocked` 多一道判斷：**技能卡所屬模組沒啟用時不鎖**。

落地：`SI_DEBT`（把高利卡債整合成低利貸）的「投資自己」需要 `SKL_BOOK`。主題上也站得住腳——卡債整合本來就是「知道有這條路的人才做得到」的事。

## 六、設計鐵律 4：本批刻意重定基線

README 鐵律 4 要求「行為變更掛在開關後面，開關全關時 `simtest` 要與上一版逐項相同」。**這批沒有掛開關，基線位移了**，這是 Brian 看過前後數字後的決定（選項 A：當成一次刻意改版並記錄新指紋），不是漏做。

技術上也說明一下為什麼沒有選「掛開關」：既有的 `since` 機制只能「整條效果略過」，能蓋住新增的效果（紅包、幸福感），但蓋不住這批的另外四類改動——標籤變更（`LE04`／`LE13`）、選項成本變更（`SI_MBA`）、既有效果的參數變更（`LE07` 的 factor）、旗標欄位（`oncePerLife`／`propertyClaim`）。要全部蓋住需要另做一套內容版本切換機制，不是加一個開關就好。

500 局 `simtest` 前後對照（S25d → S26），24 項指標動了 17 項：

| 指標 | S25d | S26 |
|---|---|---|
| 全局中位 | 62 | 60 |
| 全局 P90 | 78 | 75 |
| 免費點占比 | 43.9 | 43.3 |
| 畢業人次 | 920 | 897 |
| 跌落率 | 8.4 | 6.9 |
| NPC_STEADY 破產率／自由率／淨值中位 | 7.7／62.3／1483 | 7.0／60.9／1405 |
| NPC_LEVER 破產率／自由率／淨值中位 | 1.2／91.8／2027 | 0.8／88.2／1849 |
| NPC_VC 自由率／淨值中位 | 88.4／2337 | 88.8／2251 |

方向可以解釋，也符合這批的設計意圖：**破產率與跌落率下降**（保險、健康、法律知識現在真的會減少損失），**淨值中位與畢業人次略降**（自我投資的成本改成依月薪計價後變貴了，`SI_MBA` 更是從 60 漲到 200）。整體是「更難累積財富、但更不容易被一次意外打垮」，這正是把風險移轉工具做成真的有用之後該有的樣子。

**往後的鐵律 4 比對，以本版為新基線。**

## 七、卡片工坊（`card_editor.html`）重寫

原本那版查下來有幾個問題，合起來的結果是「人生卡片這個牌堆實質上編不了」：

1. 卡包下拉選單漏掉 `v10`，那一整包碰不到
2. 類型篩選寫死 `"LIFE"`，但資料裡的值是 `LIFE_EVENT`／`SELF_INVEST`／`CHOICE`／`SPECIAL`，選了會篩出 0 張
3. 表單只有 id／title／group／stage／subtitle／flavor 加投資與商城的數值欄位——**沒有 `eduNote`、沒有 `effects`、沒有 `decision`**，也就是人生卡真正要改的三樣東西都不在裡面
4. 表單裡的 `subtitle` 欄位，遊戲根本沒有渲染它（查過 `src/ui/*.js`，沒有任何一處讀 `.subtitle`），填了不會顯示
5. 只能「複製 JSON 再自己貼回檔案」，沒有存檔

改版後：

- 卡包／牌堆／kind 三層篩選**全部從實際資料長出來**，不再寫死
- 表單涵蓋 `title`／`flavor`／`eduNote`／`tags`／`moduleReq`／限次／小孩閘門／`payload`（依 kind 自動切換欄位）／`effects`／`decision`，另外附一個「完整 JSON」編輯區，表單沒有的欄位一律能改，雙向同步
- 小孩閘門依牌堆自動用對的欄位名（MALL 用 `payload.reqChild`、LIFESTYLE／LIFE_EVENT 用 `requiresChildSinceS12`）——這是會靜靜失效的那種錯誤
- 驗證器就地跑：id 重複、未知的 op、牌堆欄位名寫錯、機會卡缺數值欄位、金額量級疑似把千元寫成元、選項有 `costSalaryMult` 卻沒有回退 `cost`（沒薪水的玩家會變成免費）
- **引擎認得哪些 op 由 `build/bundle.js` 從引擎原始碼掃出來注入**（與 `tests/contentcheck.js` 同源），不再手抄一份會過時的清單
- 真的能存檔：支援 File System Access API 的瀏覽器直接跳存檔視窗，其餘瀏覽器下載檔案；輸出格式（2 空格縮排、UTF-8 不跳脫中文、結尾換行）與 repo 內既有的內容包一致，所以存回去之後 `git diff` 只會顯示真正改動的那幾行
- 新增／複製／刪除卡片；離開頁面前若有未存檔的修改會攔一下

### 8.1 順手修掉的顯示錯誤

`ui.effectSummary` 有三個一直在說謊的地方，這批一起修：

### 8.2 動到一支既有測試

`tests/s19test.js` 的 `endTurnSafe()` 原本在 `E.syncPhase()` **之前**清 `S.bookkeeping`，但記帳題是 `afterResolve`／`syncPhase` 之後才重建的。牌堆多了兩張卡、抽牌順序位移之後，那幾個回合真的產生了記帳題，`END_TURN` 就卡在 `BOOKKEEPING_INCOMPLETE`，連帶兩項斷言失敗。這支測的是商城的每輪計數、不是記帳流程，所以把清除移到送出 `END_TURN` 之前。**這是修測試的既有時序錯誤，不是為了讓紅燈變綠而放寬斷言**——16 項斷言一項沒動。

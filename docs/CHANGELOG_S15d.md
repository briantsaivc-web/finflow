## 一、你遇到的那一局，根因是什麼

**你的截圖直接指出了兇手**，我補上證據鏈：

> 系統訊息　第 10 輪　📈 **carrie「狂潮小型股（投機）」帳上獲利 +102%**

`stockGainAlertPct`（帳上獲利達門檻提示停利）在 **`onRoundEnd` 對「所有真人」發**，不管輪到誰。carrie 的投機股當輪 +20.1%、未實現獲利越過 100% 門檻 → 系統推一筆 `STOCK_GAIN` 決策給 **carrie**，而當時輪到的是 **Brian**。

接著三條路同時堵死：

| 誰 | 做什麼 | 結果 |
|---|---|---|
| carrie | 回答自己的停利提示 | ❌ **`NOT_YOUR_TURN`** ← 你看到的「這個動作現在不能做」 |
| Brian | 擲骰 | ❌ `WRONG_PHASE`（階段是 DECISION） |
| Brian | 結束回合 | ❌ `PENDING_DECISION` |

**沒有任何一條路走得通 → 整局掛死。** 這與你截圖上的矛盾完全吻合：Brian 的卡片寫「你的回合」，畫面中央卻寫「等待 carrie 做決定中」。

### 為什麼是多人局才會中

`STOCK_GAIN` **只發給真人**（電腦玩家直接跳過）。單機局只有一個真人，而他就是 0 號座位＝每一輪的起點，所以決策永遠屬於當前玩家。**只有兩個以上真人的多人局會踩到。**

這也解釋了為什麼我先前的 1,000 局壓力測試與 1,200 局死結偵測器全綠——**它們都是全電腦玩家的局，這條路根本不會被走到。**

### 順帶發現的第二個 bug（更危險）

同一個根因還有另一面：`DECIDE` 的處理一律用「當前回合玩家」當主體。實測構造驗證：

```
carrie 回答自己的決策      ❌ 被拒：NOT_YOUR_TURN
Brian  代答 carrie 的決策  ✅ 通過      ← 而且效果會套到 Brian 身上
```

**如果 UI 曾經讓當前玩家看到別人的決策卡並按下去，停利／賣股的效果會落在錯的人頭上。** 這比死結更難察覺，因為它不會當機，只會把帳算到別人身上。

## 二、修了什麼

### ① 引擎：決策的主體是「擁有者」，不是當前玩家

- `DECIDE` 加入條件式非回合白名單（沿用 S15a 建的 `E.OFF_TURN_CONDITIONAL` 機制）：**決策的擁有者永遠答得了自己的決策，不管輪到誰。**
- `E.resolveDecision` / `E.afterResolve` 改用決策擁有者，不再用當前玩家。
- 新增 `NOT_YOUR_DECISION`：**不准代答別人的決策**。

### ② `afterResolve` 不得污染當前玩家的回合狀態

`turnResolved` 與 `bookkeeping` 都是「當前回合玩家」的狀態。非當前玩家答完自己的決策時不能動它們——否則會出現：

- 當前玩家**不用擲骰就能結束回合**（`turnResolved` 被別人設成 true）；
- 當前玩家被掛上**別人的記帳題**而結束不了回合。

兩者都已寫成 T-91 的斷言。

### ③ UI：決策卡也要畫給擁有者

`ui.renderCenter` 原本把決策卡渲染給當前回合玩家。在 carrie 的裝置上，她的停利卡是**拿 Brian 的數字在畫**。已改為以決策擁有者為主體——這是引擎那個 bug 在 UI 層的鏡像，測試才抓出來的。

### ④ 多人局的卡住防護（S15a 漏掉的一整塊）

**我上一批的防護在多人局完全沒有生效。** 多人局把 `ui.tick` 換成了 `mpAfter()`，所以 S15a 加的進度指紋偵測與診斷面板，多人局一次都不會執行。而 `mpSend` 被拒時只丟一句 toast 就結束，電腦玩家的迴圈再也不會被叫起——**「看到『這動作不能』就掛了」正是掛在這裡。**

補上：

- `mpSend` 被拒時把**原因**一起顯示（不再只是「這個動作現在不能做」），連續 3 次就開診斷面板。
- `mpAfter` 加上同一套進度偵測；等真人回應、或待決事項屬於某個真人時**安靜停下**（那是正當等待，不是卡住），房主不代跑。
- 診斷面板新增 **「待決屬於誰（座位幾號）」** 與 **「我是座位幾號」**——這次就是靠這兩項才定位到根因。
- **多人局的救援改成「重新同步這一局」**：從房間紀錄重新載入。原本的「跳過這一位」會直接改本機狀態，在多人局會讓各端的 actionLog 對不起來，等於用一個更難查的錯換掉一個看得見的錯。說明文字也跟著分模式（原本不管哪種模式都寫「按『跳過這一位』」，但多人局根本沒有那顆鈕）。

## 三、我怎麼找到的（方法本身值得記下來）

前兩次我用**猜的**：先猜是下市清算打到非當前玩家，再猜是非回合逛商城把自己買到負現金。**兩次都沒中。**

依「同一子任務錯兩次就換方法」，我改成**寫一個通用不變式偵測器**：用全真人座位跑 250 局，在每一個動作前後檢查

> 若存在待決事項，它的擁有者是否就是當前玩家？若不是，擁有者答得了嗎？

一次就抓到，而且只抓到一種：

```
250 局（全真人座位）
    6  STOCK_GAIN 屬於非當前玩家（修前：擁有者答不了＝死結／修後：擁有者答得了）
死結局數：0
```

**教訓**：全 NPC 的模擬對「只發生在真人身上」的路徑是盲的。往後任何「只對真人做」的程式碼（`if(p.isNPC) return;`），都必須另外用真人座位的模擬跑一遍——這條我加進偵測器常備了。

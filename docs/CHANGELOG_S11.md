## 1. 自動記帳：分類別激活，選項常駐不跳問

依你的指示「要分類、可以用激活方式、選項本來就在、不用每次問」。

### 熟練度的單位是「象限」

遊戲問玩家的問題就是「這一筆屬於資產／負債／收入／支出哪一格」，所以熟練度就照這四格各自計：

- **答對**該象限 → 該象限的連續紀錄 +1
- **答錯** → 把「那一筆的正確象限」歸零（是連續答對，不是累計答對）
- 連續答對達 `bkMasteryStreak`（預設 **5**）→ 該象限**永久解鎖**

解鎖是永久的（`bkUnlocked`），但**解鎖不等於自動開啟**（`bkAuto` 預設全關）。開不開由玩家自己決定，隨時可以改回手記。

### 選項一直都在

記帳面板下方常駐一個四列的區塊，未解鎖時顯示鎖頭與進度（「連續答對 3 / 5（答錯歸零）」），解鎖後變成可按的「改成自動」。不會在達標那一刻跳出來打斷你，也不會錯過了就沒了。

新增引擎動作 `SET_BK_AUTO`：沒解鎖不給開（`NOT_UNLOCKED`），不合法的象限也擋。開啟後 `buildBookkeeping` 直接略過該象限的分錄——**帳照記，只是不用你分類**。報表上的分類正確率也只會繼續算你自己分的那些。

## 2. 定期定額買進與股息再投入

### 共用的「預算 → 買得起幾張 → 餘額留到下期」

`units` 在引擎裡是整數（張），所以固定金額不見得剛好買得到整張。做法是：

```
預算 = 上期餘額 + 本期金額
張數 = floor(預算 / 現價)
實扣現金 = 張數 × 現價
餘額 = 預算 − 實扣現金   ← 留到下期
```

**餘額不是現金**，是「還沒湊滿一張的預算」——現金只在真的買進時才動，帳上不會多出一筆沒人管的錢。這也剛好把定期定額的重點演出來：同樣的金額，價格低的時候買到比較多張。

### 定期定額

每次發薪自動扣。**現金不足就直接跳過那一期**並記次（`missed`），不會替玩家借錢、也不會補扣。標的下市則自動停扣。面板上會顯示已扣幾期、買到幾張、平均成本 vs 現價、以及跳過幾期。

### 股息再投入

配息本來就隨發薪結算進了現金，所以再投入是排在 `ns.modules.onPayday` **之後**執行——順序不可對調，否則會用「還沒入帳的股息」去買股票。不配息的股票不給開（`NO_DIVIDEND`）。

面板上的說明沒有只講好話：

> 複利是這樣長出來的，但它同時也把風險越押越重在同一個標的上。

## 3. 自動執行：沿用既有機制，沒有另做一套

**查證後決定不新增系統。** 引擎裡的 `PLAYER_LEAVE` / `PLAYER_RETURN`（多人的「離席代打」）已經在做需要的每一件事：把座位轉成電腦（`flags.leftHuman`）、清掉屬於離席者的記帳題、代答懸置中的互動，之後可以認回。而且它是引擎動作，走 `dispatch → actionLog`，重放與多人 lockstep 都吃得到。

所以本階做的是**把它接到單人局的操作區**，不是重寫：

- 操作區新增「🤖 自動執行」按鈕，按下去先解釋清楚會發生什麼，確認才交出去
- 代打中該顆鈕變成「**🙋 我來（接回操作）**」，並在畫面下方掛一條金色橫幅「🤖 電腦代打中」、盤面加金色虛線外框
- 代打用保守型（`NPC_SAFE`）的邏輯

說明文字也照實寫：

> 代打不是最佳解，只是「看到就處理」的基準行為。離開越久，帳面越可能長成你不想要的樣子。

## 5. 未預期發現：一條測試通過的理由是錯的

第一輪反向驗證時，**第六項沒被抓到**——把「離席時清掉記帳題」的那行程式刪掉，T-66 照樣通過。

原因：我原本寫的是

```js
assert(!(S.bookkeeping && S.bookkeeping.playerId===0), "代打期間不得留著記帳題目給不在的人");
```

但測試跑到那裡時**本來就沒有記帳題**（還在第一輪、玩家還沒產生任何要分類的分錄），所以這條斷言是因為「碰巧沒有」而通過，不是因為機制正確。

改法：先真的造出一份屬於我的記帳題並斷言它存在（**前置條件也要驗**），再離席，才驗得到清除行為；並多驗一條「代打期間不得再長出新的記帳題」。改完之後倒回去測，這項就抓得到了。

這跟 S10 那條「`if(typeof document)` 導致測試從沒跑過」是同一類問題的不同長相：**測試通過不等於驗過了**。往後任何「斷言某個東西不存在」的測試，都要先斷言前置條件成立，否則它只是在驗一個空狀態。

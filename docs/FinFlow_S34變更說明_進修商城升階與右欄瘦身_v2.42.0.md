# FinFlow S34 變更說明：進修商城升階、右欄瘦身、隨時可看

- 版本：**v2.42.0-S34**（前一版 v2.41.0-S33）
- 日期：2026-09-05
- 一句話：三項實測回饋的介面修正。**引擎與內容一行都沒動**，500 局模擬與 S33 逐字元相同。

---

## 1. 進修商城拉到跟人生商城同一階

S31 把進修商城放進人生商城的第一排，理由是「進修本來就是一種消費決策」。**這個理由在道理上成立，在動線上失敗了**——玩家想學技能時不會先想到去點「買東西」。

現在它是操作區的一顆按鈕，跟人生商城平起平坐：

```
🤝 交易所　🛍 人生商城　🎓 進修商城　🤖 自動執行　📋 復盤　🏁 結束遊戲
```

- 人生商城裡**不再有**進修商城入口
- **技能證書牆兩邊都留著**（人生商城裡一顆、進修商城表頭一顆）——這是 S31 你裁示的「兩邊都有」，沒有動
- 測試會驗兩顆按鈕是操作區**同一層的兄弟節點且樣式同級**，不是「看起來像」

---

## 2. 右欄不再列「已具備：…」

原本右欄永遠佔著一格「學習與準備」，內容是一份已具備技能的清單。**那份清單在進修商城的表頭與技能證書牆裡都看得到，右欄再列一次只是佔位置**——你圈掉的就是這個。

改成**只有真的有事在進行才出現**：

| 狀態 | 右欄 |
|---|---|
| 正在進修 | ✅ 顯示（課程名、進度條、放棄學習） |
| 剛學完、冷卻中 | ✅ 顯示（剩幾輪可以再開始） |
| 什麼都沒在做 | ❌ **整區不渲染**（連 DOM 節點都不留） |

順帶拿掉右欄那顆「📖 進修（自己找資源）」——入口已經升到操作區，留著是第三個重複入口。

**這是搬家不是刪除**：測試會驗已具備的技能在證書牆與進修商城表頭都還查得到。

---

## 3. 不能進修的時段照樣打得開

你的原話：「玩家會趁空檔研究內容，只是不能執行（類似人生商城的作法）」。

新增 `ui.skillEnrolBlock(S, p)`——回傳「現在為什麼不能報名」的一句話，回空字串就是可以報名。**操作區按鈕的 title、進修商城的表頭提示、每一列的停用理由，三處共用這同一份判斷**，才不會出現「按鈕說可以、按下去被引擎擋掉」。判斷條件的順序對齊引擎 `START_SKILL` 的守門，一條不多一條不少：

破產程序中 → 遊戲已結束 → 已進入自由圈 → 正在進修 → 冷卻中 → 不是你的操作時機 → 決策或記帳還沒處理完

面板的行為：

- **永遠打得開**（本局沒開進修時按鈕才停用，而且會說明原因，不是消失）
- 不能報名時，表頭出現金色的「👀 現在只能看——<理由>」
- 每一列課程**照樣完整顯示**（學費、輪數、先修、hint），只是全部停用
- 可以報名時，付得起又有先修的那些列必須是可按的——測試特別驗這一條，免得改著改著把大家一起關掉

**引擎的 `START_SKILL` 守門一個字都沒改。** 這裡做的只是讓畫面提前說出引擎會說的話。

## 4. 順手處理掉的一個連帶問題（不靜默處理）

互動教學第 13 步原本錨在右欄的 `[data-tut="learn"]`。第 2 項改完之後，那個節點在常態畫面下不存在了——教學會指到空的地方。

錨點改指 `#btnSkill`，文案同步重寫（zone 也從「右欄」改成「中欄」）。測試會驗**錨點在常態畫面下必須找得到**，這條守則以後也擋得住同類問題。

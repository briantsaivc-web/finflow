# FinFlow 變更說明 — 多人連線實測 V1 修訂 v2.2.1

日期：2026-08-27　·　基底：v2.2.0（M12-A）　·　來源：NB＋iPad 首次實測回饋五項

## 你回報的五件事，逐一處理

**1. 房號改 2 碼阿拉伯數字** ✅
房號從 6 碼英數改為 00–99 兩碼數字，輸入框自動叫出數字鍵盤。因為只有 100 個號碼，建房時會自動避開 24 小時內還活著的同號房、蓋掉超過 24 小時的舊房——這需要 Firebase 規則配合，**請到 Firebase 控制台把「規則」重貼一次**（新版指南步驟三的整段，改了一行），否則撞到舊房號時會建房失敗。

**2. P2P 隨時可以，不必等銀行額度用完** ✅
原本引擎規定「借款人銀行額度沒用完就拒絕 P2P」。現在：真人之間的 P2P 隨時可談——提出後對方畫面會跳出邀約視窗，對方按「接受」才成立（跨裝置親自回應，不再由系統代答）。若借款的一方銀行額度還沒用完，邀約視窗和借貸面板都會出現提醒「💡 銀行利率通常更低，可先用貸款」，但要成交隨時可以。電腦對手維持原邏輯（NPC 不借高利貸、放款看水位），這條理性線不動。

**3. Bug：A 賣資產給 B 被「不是你的回合」擋掉、B 也收不到** ✅
抓到了，是兩個寫死的老 bug 疊在一起：
- 回應按鈕把動作掛在「當前回合玩家」身上——B 按「買下」時系統以為是 A 在操作，被權限檢查擋下。現改為掛在當事人身上（買方回報價、賣方回還價），引擎同時加上「只有當事人能回應」的防呆。
- 報價視窗若被關掉就再也叫不回來。現在只要有等你回應的報價／還價／借貸邀約，畫面中央會常駐一條「💰 點這裡回應」提示條，點了隨時重開；賣方那邊也會看到「等待回應中（可取消報價）」。

**4. 交易可指定特定人，也可廣播給所有人** ✅
轉讓面板的「賣給誰」多了「📢 廣播給所有人」：真人玩家各自畫面跳出搶購視窗，**先搶先贏**（同時按的話由同步序自然裁決）；所有真人都婉拒才輪詢電腦，電腦也不要就流標。指定特定人的原流程不變。

**5. Bug：iPad 玩家自己的回合開不了交易所** ✅
根因：交易所與 P2P 面板裡各有一處寫死「回合玩家＝0 號」（單機時代的殘留），iPad 坐 1 號座位永遠打不開。已改為依自己的座位判斷。這是上次「playerId:0 → ui.myId()」全面清查的漏網之魚——這次把兩個面板的入口一併補上。

## 要你做的一件事

到 Firebase 控制台 → Realtime Database →「規則」分頁 → 把新版《Firebase 設定指南》步驟三的整段規則重貼、發布（一分鐘）。金鑰不用動，各裝置也不用重貼——只有規則那一行變了（允許回收超過 24 小時的舊房號）。然後把 v2.2.1 的 index.html 拖上 Netlify，所有裝置重新整理頁面即可（版本不同的人會被擋在房外並提示重新整理）。

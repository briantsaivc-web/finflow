## 零、先說兩件「結論跟回報不一樣」的事

實測回饋六項裡有兩項，查下去的結果跟原本的假設不同。先講，因為它們決定了後面怎麼修。

### （1）結算彙總沒有壞掉——壞的是分類

回報是「前幾輪事件會統整為一個表，後面又變回個別跳提示」。我開瀏覽器實跑 30 輪逐輪記錄：

```
彙總觸發 27 次／開起來 27 次
沒出現的三輪＝第 11、22、23 輪——那三輪玩家正在「停走」，帳上沒有任何異動
仍然一則一則跳出來的 toast：17 則
```

那 17 則的內容才是關鍵：

| 類型 | 則數 |
|---|---|
| 景氣轉入 | 5 |
| 央行升息／降息 | 5 |
| 停走通知 | 3 |
| 政策事件 | 1 |
| 失業 | 1 |
| 其他 | 2 |

**全部都是廣播資訊。** S16 訂的規則是「good 靜音、warn 照跳」，理由是 warn 代表要當下注意。但 `warn` 這個維度分的是**好消息／壞消息**，不是**要不要你現在動手**。前幾輪安靜是因為總經引擎還沒開始循環；第 6 輪之後景氣與利率每隔幾輪就來一次，於是玩家的體感就是「彙總不見了」。

### （2）人力成本記在收入，記帳沒錯，錯的是標籤

回報是「人力成本上升卻記到收入下降，怪怪的」。查證：

- 肇事者是 **MK05「最低工資調漲」**，效果 `ASSET_INCOME_MULT ×0.85` 打在 BUSINESS 上，標籤寫「人事成本上升」。
- 但這個遊戲**所有資產存的都是淨額**：房地產存 `租金 − 成本`（欄位就叫「淨租金」），事業存 `monthlyProfit`。全遊戲沒有任何一處把資產的營運成本拆成獨立支出行。
- 卡片自己的 eduNote 也寫：「營運成本上升會直接吃掉事業的**淨利**。」

所以扣淨利是對的、記在收入欄也是對的。難讀的是**摘要看起來像一筆支出，數字卻出現在收入欄**。同款問題還有 MK08「通路抽成」。

改成真的發到 EXPENSE 需要新增引擎 op，而且會跟其他所有資產的淨額慣例不一致、動到被動收入與自由進度的分母——**代價遠大於收益，這次不做**。改標籤把因果講完即可。

## 一、六項各自怎麼修

### 1＋4　通知分三類（系統／自己動作／其他玩家引發）

新增 topic 維度，靜音規則從「看 cls」改成「看 topic」：

```js
ui.CAT = { SYS:"SYS", MINE:"MINE", OTHERS:"OTHERS" };
ui.toastMuted = function(cls, topic){
  if(!ui.turnSummaryOn()) return false;
  if(topic==="SYS") return true;      // 廣播資訊：收進彙總
  if(cls==="warn")  return false;     // 要你當下處理的：照跳
  return true;
};
ui.toastSys = function(msg, cls, ms){ return ui.toast(msg, cls, ms, "SYS"); };
```

八處系統類通知改走 `toastSys`：景氣轉入、央行升降息、政策事件／天災、償債能力警示、終止上市、失業、停走、TURNS_SKIPPED。

彙總畫面同步分三段列示，**每段有自己的小計**，最下面才是本輪合計：

```
🌐 系統與大環境　17 筆　　+72,810 …
🙋 你自己的動作　 3 筆　　+50,500 …
👥 其他玩家引發　 1 筆　　      …
──────────────────────
本輪合計
```

分錄歸類靠 `ui.entryCat(e, meId)`：先看 eduTags（`referral` → 其他玩家；`inflation`／`rate`／`event`／`payday`／`layoff` 等 → 系統），再看摘要關鍵字，最後看摘要裡有沒有出現**別的玩家的名字**（P2P、合資、轉讓幾乎都會帶對方的名字）。都不中就歸「你自己的動作」。

**這是推斷不是紀錄**：分錄本身沒有記「誰造成的」。分錯只會列在別的段落，不影響任何數字，三段小計相加恆等於本輪合計。要做到百分之百準確得在引擎的 `ledger.post` 加欄位、動到一百多個呼叫點，這次沒做。

順手修掉一個相關缺陷：大事件橫幅 `#bcast` 的 z-index 是 820、overlay 是 700，會蓋在結算畫面的標題上。開結算時把橫幅收掉（內容本來就在彙總與系統訊息裡）。

**實測前後對照（同一顆種子、同樣 30 輪）**

| | S17 | S18 |
|---|---|---|
| 彙總開起來 | 27／27 | 27／27 |
| 一則一則跳出來的 toast | **17 則** | **0 則** |
| 收進彙總的提示 | 11 則 | 28 則 |

需要你當下處理的 warn（被拒、追繳、出價、邀約、記帳答錯）**照跳不誤**，T-94 有專門的斷言擋著。

### 3　系統訊息補上「決定」

引擎在 `DECIDE` 解決後補發一個純輸出事件：

```js
E.ev("DECISION_RESOLVED",{ playerId:dOwner.id, kind:d.kind, cardId:d.cardId||null,
                           optionId:action.payload.optionId, title:d.title||null });
```

`E.ev` 只往 `E._events` 陣列丟東西、完全不碰 `S`，所以不影響重放與平衡（下面有 500 局指紋逐項相同的證據）。文案由 UI 端查——引擎不碰文案。

UI 端把決定**接回同一行**，而不是另開一行：

```
第11輪 🎲 槓桿哥 擲 1 點 → 機會　決定：夜市小吃攤（頂讓）→ 用現金
```

三個細節：

- optionId 有時候直接就是一張卡的 id（選機會卡）。`ui.decisionOptionLabel` 會查回卡名，不把 `OPS_BZ5` 這種代號端給玩家。
- 一次擲骰可能連做兩個決定（先選卡、再選付款方式），接成 `A → B`，不會變成兩個「決定：」。
- 純揭曉型的決策（ACK／TRIAL_RESULT／BLESSING／SKILL_RESULT／DIGITAL_RESULT）不寫「決定」——那些沒有選擇可言。

### 2　成本型卡片標籤

| 卡 | 舊標籤 | 新標籤 |
|---|---|---|
| MK05 最低工資調漲 | 人事成本上升 | 人事成本上升 **→ 事業淨利下降** |
| MK08 外送平台抽成調高 | 通路抽成 | 通路抽成調高 **→ 事業淨利下降** |

另外在分錄列補一句說明：偵測到「純收入減少、且摘要含成本／抽成／費用／工資字樣」時，加註

> 資產收入記的是淨額（收入−營運成本），所以成本上升會直接扣在收入這一欄

純字串變更，引擎位元不受影響。

### 5　玩家卡壓矮（不是改欄數）

回報是「左側玩家一排 3 個，比較不會排到三排、壓縮到系統訊息」。**先量再改**：房間上限就是 4 人，2 欄排 2 排、3 欄排 3+1 也是 2 排。

| 1440×900 | 玩家區高 | 每張卡高 | 排數 | 系統訊息看得到 |
|---|---|---|---|---|
| S17　2 欄 | 361px | 173px | 2 | 11 則 |
| S17　3 欄 | 361px | 173px | 2 | 11 則 |

**一模一樣。** 改欄數不會多出一行訊息——真正吃掉高度的是卡片本身 173px。所以改的是卡片內容：6 行收成 3 行。

- 狀態（等待／思考中／你的回合）併進名字那一列的尾端
- 被動收入與資產筆數併成一行：`18,120 ／ 6 筆`
- 「每輪紀錄」併進幸福感／夢想那一列

| 玩家區（2 排） | 361px | **252px** | −109px |
| 系統訊息可視高 | 509px | **618px** | |

## 四、還沒驗到的（UNKNOWN）

1. **分類準不準要靠實戰**。`entryCat` 是關鍵字推斷，不是引擎紀錄。看到分錯的請截圖告訴我是哪一筆，我加規則——或者評估要不要在 `ledger.post` 加一個欄位從源頭記。
2. **「0 則 toast」是那一局的結果**，不是保證。那 30 輪剛好沒有觸發追繳、被拒、拍賣邀約這些該跳的事件。要你實測確認「該跳的還會跳」。
3. Firebase 跨裝置連線、iPad Safari 實際觸控，沿用前幾批的 UNKNOWN。

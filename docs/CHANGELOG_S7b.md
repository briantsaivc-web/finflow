## 1. 投機股下市（先警告再下市）

**只有投機股會下市。** 第一版做成「所有股票」，量出來 80 局裡下市 88 次——大盤 ETF 和高股息股都在歸零，四檔股票會在中後期被清空，股市內容整個消失。改成只有 `STK_SPEC 星火小型股（投機）` 帶 `delistable` 旗標。

### 流程

1. **警示**：股價 ≤ 面額 ×20%（跌掉八成）**且**景氣踏入蕭條 → 發「償債能力警示」，持股者**跳卡**
2. **緩衝**：預設 2 輪，玩家可停損；期間價格回來或景氣改善 → **警示解除**
3. **下市**：緩衝期滿且條件仍成立 → 持股歸零，該檔股票從此不再報價、不再出現在牌堆

### 警示卡把差額攤開

| | |
|---|---|
| 你的持股市值 | 96,000 |
| 當初投入 | 400,000 |
| 現在停損拿得回 | 96,000 |
| 若下市 | **0（但融資的債還在）** |

> 撈底的人常說「都跌成這樣了還能跌到哪」——能，可以跌到歸零。

**融資部位是重點**：下市走的是 `sellAsset(…, 0)` 的同一套清算邏輯，所以股票沒了，融資借款會**自動轉成信貸留在身上**。T-57 對這條有專門斷言。

## 2. 新創寒冬（估值下修＋少數陣亡）

景氣轉入衰退／蕭條時，每筆新創先擲一次陣亡（預設 20%），活下來的砍估值（衰退 ×0.7、蕭條 ×0.45），`postMoney` 一併下修。

40 次構造測試：**陣亡 10 次、下修 30 次**，沒有全滅也沒有全活。景氣變好時完全不作用。

> 教學點：沒有現金流的資產在寒冬裡最脆弱——它的價值完全靠別人願意出多少錢。

## 3. 木作與居家修繕（SKL_CARPENTRY）

租金 **+8%**、空租機率 **減半**。與水電刻意不重疊：**水電治的是「壞掉要花錢」，木工治的是「租得掉、租得好」**。

實作上用資產的 `carpentry` 旗標保證**冪等**——學成技能時手上的房子一次加成，之後每次買房也會套用，重複呼叫不會重複加。空租中的物件加在「復租後會恢復的租金」上，而不是當下的 0。

## 4. 這一階最重要的發現：**電腦玩家從來不買股票，也買不起新創**

驗收時「停損 0 次、新創寒冬 0 次」，我沒有當成雜訊放過，直接量了持有狀況：

> **120 人次中，持有股票 0、持有新創 0。**
> 電腦玩家的買入紀錄只有：不動產 386 次、事業 1,816 次。

原因兩個，都不是這一階造成的：

1. **股票卡在 v2.3.1 就被移出機會牌堆**（封存 10 張），股市改成「股市面板」進入——那是**真人專屬的 UI 動作**，電腦玩家沒有對應的 action。
2. **新創買不起**：最便宜的新創要 1,500，而電腦玩家的現金高水位中位數只有約 470、P90 約 1,100。

### 這件事的意義（要說清楚）

**過去所有的平衡數據，都是在「只買房產與事業」的電腦玩家身上量出來的。** M1 股市與 M3 新創對電腦玩家形同虛設。這代表：

- 進圈率、跌回率、破產率這些指標，反映的是房產＋事業這條路的難度，不是整個遊戲的難度
- 任何跟股票、新創有關的平衡改動，**模擬都量不出來**——包括這一階的下市與寒冬
- 特殊機會的門檻（平均 5,575）也遠超電腦玩家的現金水位，同樣量不到

**這一階的兩個新機制因此改用直接單元測試覆蓋**（T-57 的 40 次寒冬構造測試、下市的完整流程測試），驗收腳本也改成：偵測到「電腦玩家不持有該類資產」時，明確印出原因而不是靜默通過。

**要不要讓電腦玩家也買股票／新創，是一個獨立的決定**——它會把所有平衡基線整個移動一次。我沒有在這一階自作主張去改。

## 5. 驗收

### 自測 57／57 通過（新增 T-57）

| 檢查 | 內容 |
|---|---|
| 下市 | 非蕭條不觸發；**非投機股即使跌到谷底也不下市**；警示→緩衝→歸零；**融資債留存**；價格回來可解除；停損拿回市值；下市後不再出現在牌堆；可關閉 |
| 新創寒冬 | 40 次構造測試有死有活；存活者估值與 postMoney 一併下修且為正有限數；景氣變好不作用 |
| 木工 | 租金 +8%；**冪等**（重複呼叫不重複加）；空租中加在復租後的租金上；空租機率減半；**同設定跑兩次完全相同** |

**反向驗證**：單獨打進未修補的 S7a 會失敗（56/57）。

**一個我寫錯又修掉的斷言**：原本斷言「木工技能不得改變 RNG 呼叫次數」——那是抄水電技能的紀律，但兩者不同。水電只縮放金額，序列必須不變；木工改變的是「空租有沒有發生」，而空租一旦發生會多消耗一次 `randInt`（決定空幾輪），序列本來就會不同。改成斷言真正該保證的事：**同一份狀態跑兩次結果完全相同**。

| 項目 | 結果 |

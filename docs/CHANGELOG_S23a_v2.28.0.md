# FinFlow S23a 變更說明：股息修正與下市機率制
版本 **v2.28.0-S23a**（2026-09-03）｜前一版 v2.27.0-S22（commit a14ab14）｜工程書：`FinFlow_S23工程書_股息修正_下市機率制_M9進階金融_v1.0.md`

本期只做工程書的 §1（股息）與 §2（下市）。M9 進階金融（期貨、迷因幣）留在 S23b／S23c。

---

## 0. 為什麼要改

Brian 在第 87–91 輪的每輪紀錄裡看到「股息再投入」每輪扣掉七十幾萬，懷疑帳記錯了。
逐筆核對的結論：**帳沒有錯，但它暴露了一個經濟設計上的漏洞。**

高股息股的每張股息在 S22 是「面額 × 0.4%」，**買進時算一次就定死**，價格再怎麼跌都不變。
當股價跌到面額的 16%（4,630 對 28,000），殖利率變成月 2.4%＝**年化 29%**；
股價地板是面額的 10%，在地板上年化可到 **48%**（工程書當時估 58%，實測是 48%，這裡更正）。
配上「定期定額＋股息再投入」，就是一台印鈔機——那一局的被動收入滾到每月 148 萬。

同一批討論裡 Brian 另外指出：投機股「跌到 1,200 就會倒」是固定門檻，玩兩局就被背起來了。

## 1. 股息：每輪重算（`E.stockDivPerUnit`）

每張月股息不再是買進時定死的數字，改成**每輪跟著股價與景氣重算**：

```
每張股息 = min(面額 × 月配息率, 現價 × 殖利率上限) × 景氣係數
```

| 閘門 | 值 | 效果 |
|---|---|---|
| 殖利率上限 `stockYieldCapMonthly` | 1.5%／月 | **年化 18% 封頂**（Brian 定案：房地產隨手 50%，壓太低沒人玩） |
| 景氣係數 `divMult_*` | 復甦 1.0／過熱 1.1／衰退 0.8／蕭條 0.5 | 景氣差，配息跟著砍 |

- 價格在面額 **27% 以上**時上限咬不到，正常區間的手感與 S22 完全一樣。
- 高股息股新增自己的地板 `floorMult: 0.25`（其餘檔沿用全域 0.1）。地板價 7 元時剛好卡在上限：年化**正好 18%**。這是刻意配出來的——地板與上限一起把最壞情況鎖在 Brian 指定的數字上。
- 每輪重算由 `E.restockDividends` 在 `M1.onRoundEnd`（股價更新之後、下市判定之前）執行；差額走 `INCOME_PASSIVE` 分錄，摘要寫明原因（「殖利率上限 1.5%／月」「景氣係數 ×0.5」），玩家在每輪紀錄裡看得到配息被砍。
- **買進、每輪重算、股息再投入、NPC 評分、介面顯示全部走同一個入口**，不會各算一份。

|---|---|---|---|---|
| 28（面額） | 0.112 | 4.8% | 0.112 | 4.8% |

## 2. 下市：機率制（`E.delistHazard`）

S22：投機股 **且** 蕭條 **且** 價格 ≤ 面額 20% → 警示 2 輪 → **必倒**。定值＋必倒，可以被算出來。

S23a 改成每輪擲一次，三個因子相乘：

| 因子 | 規則 |
|---|---|
| 跌幅門檻 | **每局暗抽**（`delistDdMin` 0.75 ～ `delistDdMax` 0.90 之間，種子決定、整局固定、不顯示） |
| 景氣 | 復甦／過熱 **0**；衰退 8%／輪；蕭條 25%／輪；跌破九成再**加倍** |
| 撐的時間 | 在危險區每多撐一輪 **+3%**（撐越久越危險） |

- 進危險區的第一輪**只警示不擲**（保留 S22「先警告再下市」的精神，給一輪反應時間）；之後每輪擲。
- 風險等級：<10% 低／<25% 中／其餘高。警示卡顯示等級；有 `SKL_BOOK` 或 `SKL_CPA_AUDIT` 的看得到**實際百分比與已撐輪數**。等級變了才重跳卡，不會每輪都吵。
- 哪些會倒：投機股 `delistHazardMult 1`；**成長股 0.05**（Brian 定案「很低但不是零」）；ETF 與高股息股 0。
- 下市流程（歸零、留壁紙、**融資的債轉信貸留在身上**）完全沿用 S7b，只是觸發方式換了。抽出成 `E.doDelist`。
- NPC：風險「中」以上一律停損；「低」只有保守派賣（槓桿派與創投派賭它撐過去）。
- 開關 `delistMode`：`"hazard"`（預設）／`"fixed"`（S22 行為）。

### 頻率實測（100 局，三種 NPC 陣容輪替）
| | S22 基線 | S23a |
|---|---|---|
| 投機股下市 | 88／100 局 | **90／100 局** |
| 成長股下市 | 0 | **5／100 局** |

投機股的頻率刻意維持在基線附近——Brian 要的是「猜不到」，不是「少發生」。

## 3. 順手修的（未預期發現）

1. **`E.oppCompare` 的股票月收入算錯**：寫成「現價 × 月配息率」，但引擎實際入帳是「面額 × 月配息率」，機會二選一面板顯示的數字與買下去實得的對不上（NPC 的二選一也讀這個）。已改走統一入口，**掛在 `stockDivRestock` 開關後面**——否則「開關全關要能重現基線」會斷。
2. **每張股息刻意不過 `util.r2`**：先四捨五入到分再乘張數，100 張 ETF 會差 0.2（0.132 → 0.13）。與 `E.stockRoundTripRate` 同一個道理：單價與費率留原值，金額在最後一步才收斂。這個坑是在跑鐵律 4 比對時抓到的（40／200 局有微小差異）。
3. **台灣案例事件一局只來一次**：博達、太電、解盲、雙卡四張加 `oncePerGame`，`drawCard` 的濾網與 `S.macroDone` 一起實作。同一局連炸兩次同一件事既不真實，也會把股市打到與平衡設計無關的地方。
4. **`tests/s22test.js` 把版本字串釘死在 v2.27.0-S22**，每次發版都會紅。改成驗格式與「不早於 S22」；當期的確切版本由當期測試驗。
5. **`runtests.js` 的 T-57／T-69** 驗的是固定模式那條路，已明確釘住 `delistMode="fixed"`；機率制由 `s23test.js` 驗。

## 4. 介面

- 每輪紀錄的再投入那一列，摘要從「股息再投入：〇〇 ×164」改成「**股息再投入：本期股息 760,400 → 買 〇〇 164 張**」，並在 `detail` 帶張數／單價／手續費／本期股息。這是 Brian 誤會「重複扣款」的直接原因。
- 股市面板的殖利率那一行加上「每張月股息 X（殖利率上限 1.5%／月、景氣係數 ×0.8）」——三個數字全部從同一個函式來。
- 買進面板的月配息改用重算後的數字。
- 下市警示卡：機率模式沒有倒數，改顯示風險等級；有財務技能的多看到百分比與已撐輪數；續抱按鈕的說明改成「每輪都在擲骰，撐越久機率越高」。

# FinFlow S24 變更說明：夢想里程碑擴池、每局抽路線、里程碑配圖
版本 **v2.31.0-S24**（2026-09-03）｜前一版 v2.30.0-S23c

---

## 0. 為什麼要改

Brian：「將夢想擴大為每項 20 個、每局抽五個，這樣比較不會無聊重複；除了文字還配漂亮的圖；有人達成時全服公告要加上圖片。」

對回程式的現況是：圓夢正好要 **5 點**，而每個夢想正好有 **5 條里程碑**，所以 V11 起「第 n 點 → `milestones[n-1]`」是**寫死的對應**。同一個「完登台灣百岳」，第一局是玉山→雪山→大霸，第二局還是玉山→雪山→大霸——這就是重複感的來源。

## 1. 內容：8 × 20 = 160 條里程碑，張張配圖

素材來自 `briantsaivc-web/finflow-gemini` 的 `assets/dreams/` 與 `data/dream-library-160.json`（Brian 用 ChatGPT 產的那批）。

| | 數字 |
|---|---|
| 夢想 | 8 個（id 與現行完全對得上，沒有新增或刪除） |
| 里程碑 | 每個 20 條，共 **160** 條，id 全部唯一 |
| 配圖 | **160 張，一條一張**，1280×720 WebP |
| 檔案大小 | 最小 43KB／中位 106KB／最大 185KB，總計 17MB |
| 交叉核對 | 引用 160 張、資料夾有 160 張、**缺漏 0、孤兒 0** |

`base.json` 的 `milestones` 從純字串陣列換成 `{t, img}`：

```json
{ "t": "玉山主峰｜3,952 公尺", "img": "dream_peaks/01.webp" }
```

`data/dream-library-160.json` 原樣收進 repo 當**出處紀錄**（每條留著 `imagePrompt`、授權、來源），要重畫某一張時照著那條的 prompt 生成即可。它**不進打包**——prompt 與授權欄位會白白讓 `index.html` 多 100KB，遊戲實際只讀 `base.json` 的 `{t, img}`。

## 2. 機制：每局抽路線（`E.rollDreamRoutes`）

開局為每個夢想從 20 條裡抽 `dreamCost`（5）條，存成**索引陣列** `S.dreamRoutes[dreamId]`。

存索引而不是存內容：存檔小、重放穩，日後改某一條的文案也不會讓舊存檔對不上位置。

### 兩個刻意的設計決定

**① 抽的是「哪五條」，不是順序。** 里程碑本身有敘事先後（第一顆星 → 圓滿二十顆；帆船從高雄離岸 → 橫越太平洋），抽完打亂會讓「第 5 點」講出比「第 1 點」更早的事。所以抽完依原索引排序。

**② 最後一條釘住池子的收尾**（`dreamRoutePinFinale`，預設開）。池子的第 20 條多半就是那個「完成」的節點——干卓萬山收官、登陸南極半島、學校營運到收支平衡、基金會不靠創辦人也能永續運作。不釘的話「集滿 5 點」那一刻可能講的是中途某一段，情緒收不起來。

實測（種子 4242，完登台灣百岳）抽到 `[1, 5, 11, 15, 19]`：

> 雪山主峰｜黑森林與圈谷 → 秀姑巒山｜中央山脈第二高峰 → 安東軍山｜高山湖泊群 → 三叉山｜嘉明湖門戶 → **干卓萬山｜孤立山塊收官**

20 個種子抽出 **20 種不同路線**；同種子完全重現。

### ⚠️ 相容鐵律與新開關

池子從 5 條變 20 條之後，抽選**會消耗亂數**——所有既有局的牌序都會位移，「開關全關要能逐位元重現基線」就做不下去了。所以加了開關 `dreamRoutePool`（預設 1）：關掉＝取前 5 條原序照用、**完全不取用亂數**，行為與 S23 以前一字不差。

鐵律 4 的比對加上 `dreamRoutePool:0` 後，200 局 MD5 仍是 `61c2538e…`，與 S22／S23a／S23b／S23c 基線**逐位元相同**。

池子本來就不足 5 條時（例如自訂內容包）也走同一條零亂數路徑。

## 3. 圖片：外部檔案，換圖＝同檔名覆蓋

Brian 選的方案。**這是整批唯一一個「刻意犧牲單檔完整性」的決定**，理由只有一個：換掉一張醜圖不該需要改程式、重新打包、重新發版。內嵌 base64 的話 `index.html` 會從 1.5MB 漲到 18MB 以上，而且每換一張圖就要重發一次版。

```
assets/dreams/dream_peaks/03.webp   ← 覺得醜？同檔名蓋掉，重整就換好
```

代價與配套：

| 代價 | 配套 |
|---|---|
| `index.html` 單檔帶出去、沒帶 `assets/` → 圖會 404 | **每個 `<img>` 都掛 `onerror`：載不到就把自己移除**，公告回到純文字＋emoji（＝S23 以前的樣子）。單檔離線遊玩不會壞，只是沒圖。`s24test` 有專門一項在守 |
| 從 `dist/` 部署時圖會找不到 | `build/bundle.js` 打包時把整個 `assets/` 複製一份到 `dist/`，並印出張數 |
| 檔名可能被亂寫 | `ui.dreamImgSrc` 擋掉 `..` 與反斜線；整串 `https://` 網址原樣放行（之後想換成 CDN 也不必改程式） |
| 想整包換圖 | 路徑走 config `dreamImageBase`（預設 `assets/dreams/`），會自動補結尾斜線 |

資料格式**同時吃字串（舊）與 `{t, img}`（新）**，所以內容可以分批換，不必一次到位。

## 4. 全服公告

`ui.broadcast` 多一個 `imgFile` 參數，圖放在**標題上方**；`DREAM_PROGRESS` 事件多帶 `milestoneImg`。有圖時公告停留從 6 秒拉長到 **7.5 秒**（要留時間看圖）。沒有圖時完全是原本的樣子，一個像素都沒動。

## 5. 新增的 config

| key | 預設 | 說明 |
|---|---|---|
| `dreamRoutePool` | 1 | 0＝固定用前 5 條（S23 以前行為，且不取用亂數） |
| `dreamRoutePinFinale` | 1 | 0＝最後一點也隨機抽，不釘收尾 |
| `dreamImageBase` | `assets/dreams/` | 配圖資料夾；可整包換 |

## 7. 未預期發現

1. **`s18test` 因為完全無關的理由紅掉。** 抽選消耗亂數 → 種子 7711 的牌序位移 → 那一局的一號玩家**第 4 輪就破產** → 後面沒有他的回合可以彙總，`sumOpened>=20` 就過不了。這不是 bug（1000 局閘門、gate、sim 全乾淨，那一局也正常跑到第 60 輪以 DREAM 結束），是測試對種子的脆弱性。已把該測試釘成 `dreamRoutePool:0`——它量的是版面與公告行為，跟夢想抽選無關；抽選由 `s24test` 專責驗。與 S23a 的 T-57／T-69 同一類處置。
   **順帶一提**：那支測試隱含假設「真人玩家會活滿 30 輪」。日後若有改動讓玩家更容易破產，它會再次為了錯誤的理由紅掉——值得之後改成「以他實際有幾個回合為分母」。
2. **`runtests.js` 的 T-27 驗的是舊的資料形狀**（`m.length>3` 對物件會是 `undefined`），也把「第 n 點＝第 n 條」寫死。已改成走 `E.msText`，並改驗「第 n 點＝**本局路線**的第 n 條」，另加驗事件帶得出圖檔名。
3. **`briantsaivc-web/finflow-chatgpt` 這個 repo 存取不到**：`git clone` 被工作階段的來源名單擋下，`WebFetch` 回 404。⚠️ 這是**來源不可得**，不是「查無此 repo」——GitHub 對私有 repo 給未登入者的回應本來就是 404，兩者無法分辨，標 **UNKNOWN**。後來確認素材其實已經在 `finflow-gemini` 的 `assets/dreams/` 裡，改從那裡取，問題自然解掉。
4. **`origin/main` 的程式碼比本機舊**（沒有 S23a／b／c）。只 `git checkout origin/main -- assets/dreams` 取素材，**沒有 merge**——直接合會把 S23 整批回退掉。
5. **打包的圖片計數原本數不到**：圖是分子資料夾放的，`readdirSync` 只看第一層會回報 0 張。已改成遞迴。

## 8. 待 Brian 本機驗

1. 打幾局，看同一個夢想的路線是不是真的每局不一樣（右欄夢想區與每輪紀錄都看得到里程碑文字）。
2. 推進一點圓夢進度，看全服公告的圖出不出得來、7.5 秒夠不夠看。
3. **挑一張你覺得醜的**，用同檔名蓋掉，重整看看是不是真的換掉了——這是這批要驗證的核心體驗。
4. 圖的色調與遊戲深色底搭不搭；公告的 150px 高度要不要調高一點。
5. 160 張圖 17MB：GitHub Pages 第一次載入不會全抓（只有跳到那一點時才載），但如果你覺得慢，可以把圖再壓一輪。

## 9. 下一步

- 每個夢想的池子目前是 20 條，`dreamCost` 是 5。若之後想讓圓夢點數變多（例如 7 點），抽選程式不用改，只要調 `dreamCost`。
- 里程碑文字目前是「地點｜特徵」的短句。若想回到 S23 那種更有敘事感的寫法（「玉山主峰 3,952m：台灣最高點」），改 `base.json` 的 `t` 即可，圖不用動。

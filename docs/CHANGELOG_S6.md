## 2. 架構：徽章是純呈現，不是遊戲機制

**規格書 §7-5 鐵律：徽章只給頭銜，不給任何遊戲內數值。** 一旦給錢或加成就會變成必刷任務，扭曲玩家行為並破壞平衡。

實作上把這條鐵律做成結構性保證，而不只是「我記得不要給」：

- 徽章定義放 `cards.BADGE`（自動合併、自動進 `byId`、自動享有 id 唯一性檢查）。`E.buildDecks` 只處理列舉的 deck 名，`BADGE` 不在列舉中，**絕不可能被洗進牌堆**（T-55 逐副牌堆掃過確認）。
- `ns.badges.rules` 的每一條都是**純函式**：只讀 `(S, p, ctx)`，不得寫入、不得 `ledger.post`、不得 `E.ev`、不得 `util.rand`。
- 單一條件出錯時安靜跳過，不讓整份評鑑掛掉。

### 最強的證據：引擎逐位元沒動

| 對照 | 結果 |
|---|---|
| **S6 預設設定 vs S5 預設設定，逐局比對** | **12/12 完全一致** |
| 平衡四項指標（5 seed 集 × 60 局） | 局長中位 **+0%**、進圈率 **+0%**、跌回率 **+0%**、破產率 **+0%** |

平衡指標一個小數點都沒變，因為引擎根本沒被碰到。

## 3. 復盤報告：「你的因與果」

每位玩家的分頁下方新增徽章區，依線分組成卡片（標題＋一句話說明），最後一行固定寫著「頭銜只是回顧，不影響任何遊戲數值」。沒拿到任何徽章時也給一句話：

> 沒有頭銜不代表這局白玩了——頭銜只認得出那些走得夠遠、或跌得夠深的路。

排名表也加了一欄「頭銜」，用 emoji 直接呈現，多人局一眼看得到誰拿到什麼。

## 4. 驗收結果

### 4.1 自測 55／55 通過（新增 T-55）

T-55 一條測完規格書 §4 S5 的全部驗收條件：

| 檢查 | 內容 |
|---|---|
| 內容體檢 | 每張徽章的條件函式真的存在、欄位齊全、id 不重複、互斥對象存在 |
| **互斥雙向** | 單向宣告只會擋一邊，必須 A↔B 都寫 |
| **純函式** | 同輸入同輸出；**呼叫前後整個對局 JSON 逐位元不變** |
| 互斥實測 | 直接構造兩邊都成立的狀態，確認只出現一個 |
| 相對頭銜 | 最高者才給、非最高者不給、**單人局不給**（一個人的「最」沒有意義） |
| 缺欄位防禦 | 全新玩家不炸也不誤給；單一 rule 拋錯不讓整份評鑑掛掉 |
| **不進牌堆** | 逐副牌堆掃過，確認沒有任何 BADGE |

**反向驗證**：單獨打進未修補的 S5 會失敗（54/55）。

## 5. 已知限制（誠實陳述）

**7 張徽章在 60 局 NPC 模擬中一次都沒出現**：半途而廢專家、荒廢的頻道、落袋為安、有備無患、修養有成、九命怪貓、差一步。

這**不是死規則**——新增的「可達性檢查」用兩個構造狀態（聖人／罪人）證明 21 張非相對徽章全部拿得到。這 7 張都是**真人才會走的路**：主動放棄學習、主動停利、主動買產險、把四個品格軸修滿、從自由圈跌回。電腦玩家的策略裡沒有這些選擇。

這是「NPC 走不到的路等於沒被測到」的老問題，這次的處理是**用可達性測試取代覆蓋率要求**——不強求 NPC 走完每條路，但要求每條路都證明得出走得通。

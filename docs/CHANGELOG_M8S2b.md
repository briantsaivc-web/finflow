# FinFlow 修復說明 — 新創買入面板 NaN(v2.4.1-M8S2b)

日期:2026-08-28　·　基底:v2.4.1-M8S2　·　來源:Brian 實測截圖(買「AI 客服新創 A 輪」時警告顯示「現金只剩 NaN」)

## 根因

`ui.buySimple`(買入面板)對新創卡有一條提早 return 的分支:

```js
if(cd.kind==="STARTUP"){
  pv.innerHTML=...;
  ui._buy={mode:"cash",params:{},afford:cost<=p.cash}; return;   // ← 沒有 down
}
```

其他資產類型會在後面設定 `ui._buy.down`(自備款),但**新創這條路徑漏了**。而按下「買下去」時:

```js
ui.spendGuard(util.r2(p.cash - ui._buy.down), ...)   // undefined → NaN
```

於是警告顯示「現金只剩 NaN」。更糟的是 `spendGuard` 的守門條件 `cashAfter>=buffer || cashAfter<0` 遇到 NaN 全部為 false,所以**即使現金充足,這個警告也一定會跳出來**——正是截圖的情況(現金遠超過 1,500,000 卻被擋)。

## 這不是 M8 造成的

逐版檢查確認:`index_v231.html`(你上傳的多人版原始檔)、C1、C2、M8S1、M8S2 **每一版都有這個 bug**。它是既有的 latent bug,只在買新創卡時觸發,而新創卡需要 M3 模組。

它躲過歷次驗證的原因有兩層,兩層都是我的測試覆蓋盲點:

1. **模組組合覆蓋不足**:我歷來所有模擬都用 `["M1","M2","M4","M6"]`,**從未開過 M3**,所以新創卡根本沒進過牌堆。
2. **引擎路徑從未被執行**:即使開了 M3,實測 30 局 ×4 種 preset 的結果是「買到新創 0 筆」——NPC 平常現金不夠買 1,500–2,500 的新創。單獨測試證實 NPC_VC 在現金充足時確實會買(9625→8125,數值全部有限),所以引擎邏輯本身正常,只是**在模擬中幾乎不會被觸發**。換句話說,這條路徑只有真人玩家會走。

## 修法(三層)

1. **根因**:STARTUP 分支補上 `down: cost`。
2. **防禦**:`spendGuard` 收到非有限數時直接放行並在 console 記錄,**不再把 NaN 端到玩家面前**。這是鐵律一的精神——同類問題未來不會再以 NaN 的形式出現在畫面上。
3. **引擎**:`buyAsset` 的 STARTUP 分支補上 `(pl.investAmount||0)` 等缺欄位防禦。

## 補上測試覆蓋(這次的重點)

新增 **T-38「買入面板數值完整性與 NaN 防線」**,三組斷言:

- 每張機會卡在 UI 會用到的關鍵欄位(依 kind 分別是 `price` / `investAmount`,以及租金、成本、自備款、月利潤、股權比例)都必須是有限數。
- 引擎買入新創:金額、分錄、淨值全部有限,扣款等於投資額。
- `spendGuard` 對 `NaN` / `undefined` / `Infinity` 一律放行。

**這條測試經過反向驗證**:把它植入未修復的版本會 FAIL,修復版才 PASS——確認它真的抓得到這個 bug,不是形式上的裝飾。

另外把模擬覆蓋擴到**全部 preset**(STANDARD/ADVANCED/HARDCORE/SANDBOX,含 M3),各 30 局:例外 0、NaN 0。

## 驗證結果

- 官方自測 **38/38**(新增 T-38)。
- 全 preset 模擬(含 M3)各 30 局:零例外、零 NaN。
- 關閉開關回歸:M8 未啟用時 12/12 與 C2 基線完全一致。
- 平衡三項維持區間重疊:局長中位 68.3→70.7、進圈率 47.2→43.0、跌回率 15.0→12.3。
- S2 各項驗收維持:情境卡 12/12 雙分支直測通過、兌現/錯失 38:36。

## 給後續的教訓

規格書第 5 章的測試紀律要補一條:**模組組合覆蓋**。只用單一模組組合跑模擬,會讓該組合以外的整條路徑(M3 新創、以及未來任何模組專屬內容)完全沒有被測到。往後每期驗收都應該跑過所有 preset,而不只是 STANDARD。

還有一條更深的:**NPC 跑不到的路徑,等於沒有被測到**。新創買入在模擬中 0 筆,是因為 NPC 現金門檻擋住;真人玩家卻天天在走。凡是「只有真人會做的操作」(主動進修、買新創、手動議價),都需要直接呼叫引擎函式的單元測試,不能只靠對局模擬。

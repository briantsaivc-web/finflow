## 一、多人局玩完換單機會直接結束

**回報**：「我玩多人結束後換選單機版，然後用電腦代跑，會直接結束；似乎開新局沒有清掉舊資料。」

**根因（讀碼查證）**：`ui.startCore`（單機與多人共用的開局核心）清掉了系統訊息、上次動作、檢視對象、自動擲骰計時器——**但完全沒有碰 `ui.mp`**。於是舊局的三樣東西活著進入新局：

| # | 殘留 | 後果 |
|---|---|---|
| a | `ui.mp.seat` 還是舊座位 | `ui.myId()` 回傳舊座位 → 單機局裡那個座位是電腦，**介面認為「我」是電腦** |
| b | `ui.mp.mode` 還是 `true` | `ui.dispatch` 的多人包裝是看這個旗標 → **你的動作被送去舊房間**，不是套用到本機新局 |
| c | `adapter.onAction` 訂閱與 `_hb` 心跳還活著 | **舊房間的動作會被灌進新局**——最可能就是「直接結束」的兇手 |

**為什麼平常沒事**：正式離開多人局的 `ui.mpLeaveGame` 最後有 `location.reload()`，那條路本來就乾淨。**唯獨「玩完不重整就開單機」這條路沒有任何人負責清理。**

**改法**
1. 新增 `ui.resetMultiplayer()`：停心跳、`adapter.close()`、把 `ui.mp` 整個打回乾淨的單機狀態
2. `ui.startCore` 在 `!opts.mp` 時一律呼叫它
3. `mpBeginGame` 呼叫 `startCore` 時帶 `{mp:true}`，宣告「這是多人開局」，才不會被自己的清理誤殺

測試守住三件事：清乾淨（座位 2→0、adapter 關掉、心跳停掉）、多人開局不被誤殺、清理是冪等的（連開兩局不會炸）。

## 二、辭職按鈕不要跳來跳去

**回報**：「離職進入夢想圈的按鈕不要跳來跳去，就都放在自由進度條下面，符合條件就亮金色，還不到條件就調成暗色。」

**現況（讀碼查證）**：那一整塊是 `if(isMe && p.playerStage==="INNER" && p.financiallyFree)` 才建立的——**被動收入一掉回門檻以下整塊就消失**，底下的「資產細項」全部往上跳。外圈的「重返職場」也是同樣的浮動寫法。

**改法**：兩顆都搬到自由進度條（`.freedom`）內、**永遠佔位**：

| 狀態 | 顯示 |
|---|---|
| 內圈・已達標 | 金色標題「🎉 已財務自由　進外圈後月現金流 +X」＋可按的「辭職進入自由圈」 |
| 內圈・未達標 | 灰字「**還差 被動收入 X／月，才能辭職追夢**」＋暗色停用的同一顆按鈕 |
| 外圈 | 同一個位置換成「🔙 重返職場」 |

**順便多了一個好處**：原本沒達標時什麼都不顯示，現在**隨時看得到離辭職還有多遠**——這比單純不讓按鈕跳動更有價值。

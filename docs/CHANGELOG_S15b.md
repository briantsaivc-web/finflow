## 二、交易成本

### 費率已查證，不是憑記憶寫的

工程書承諾動手前查證現行費率。查證結果（2026-08-29）：

| 項目 | 費率 | 時機 |
|---|---|---|
| 券商手續費 | **0.1425%** | 買、賣各收一次（散戶常有 6–6.5 折，遊戲取牌價） |
| 證券交易稅 | **0.3%** | **只在賣出** |
| **ETF 證券交易稅** | **0.1%** | 只在賣出 |

**ETF 稅率較低這一條是我工程書漏掉的**，查證時才發現，已一併做進去——它本身就是教材，而且剛好強化 ETF 的「基準／防禦」定位。ETF 來回成本 0.385%，一般股票 0.585%。

實作：`stockFeeRate` / `stockTaxRate` 走 config，個股可用 `taxRate` 覆寫（ETF 用它）。手續費與稅各自是獨立的分錄行（`券商手續費` / `證券交易稅`），玩家在每輪紀錄裡看得到。**賣出損益改以實際入袋計**——扣掉費稅之後才是真的賺賠。

**UI**：個股面板寫出「交易成本：手續費 0.1425%（買賣各一次）＋證交稅 0.3%（賣出）·一買一賣先賠 0.585%」；可買張數已扣掉手續費（實測：50 萬現金買晶宇科技，含費 11,538 張、不含費會誤報 11,555 張）。

### 交叉影響 X4：定期定額與股息再投入照樣收費

否則自動化會變成免手續費的套利。每張的實際成本改為 `price×(1+費率)`，預算要能同時蓋住股款與手續費，`carry`（沒湊滿一張的預算）從實際花掉的金額算起。

## 三、融資紀律閘門

下列任一條件成立時，**引擎層**擋下融資買進（UI 灰化只是提示，不能當把關）：

| 條件 | 給玩家的說法 |
|---|---|
| 淨現金流為負 | 你的淨現金流是負的——先把每月收支轉正，再談槓桿 |
| 信用評級 C | 信用評級 C——券商不會讓信用不良的人開槓桿 |
| 破產程序中 | 破產程序中不能融資 |
| 自由圈現金告急（跌落自救中） | 自由圈現金告急，先把現金救回正數 |

**交叉影響 X5**：只擋融資買股，**不擋紓困貸款與 P2P**——那是求生管道，不是放大器。現股買進也完全不受影響（已寫成斷言）。

> 設計上的一句話：問題從來不是玩家不理性，而是規則讓「賭一把」變成落後者的**最優解**。要改的是賠率結構，不是罵玩家。

## 五、必須講清楚的一件事：融資閘門在模擬中完全沒有作用

我去查了為什麼那一欄一動也不動，答案很直接：

```
depthLevel=2（預設）　電腦玩家融資動作 0 次／局終持有融資部位 0／480 人次
depthLevel=3（進階）　電腦玩家融資動作 0 次／局終持有融資部位 0／480 人次
```

**電腦玩家從來不用融資。** `ns.npc` 的決策樹裡根本沒有「開槓桿」這個分支，更沒有「落後就賭一把」。

所以：

- 模擬能證明的：**融資閘門沒有破壞平衡**（500 局逐項與 S15a 相同）。
- 模擬**證明不了**的：**它到底有沒有讓真人的賭徒行為收斂。**

這一項只有你們實測知道，我在工程書就標了 UNKNOWN，跑完數據後這個結論不變——而且現在有明確證據支持「為什麼證明不了」，不只是我的推測。

**實測時請特別留意**：閘門會不會擋到不該擋的人。最可能誤傷的是「淨現金流為負但手上現金很多」的玩家——例如剛買下大房產、月付吃掉現金流，但帳上還有幾十萬。這種人被擋住是設計意圖（現金流為負就不該再開槓桿），但實際玩起來可能覺得莫名其妙。**如果誤傷太頻繁，最小改法是把條件從「淨現金流 < 0」改成「淨現金流 < 0 且現金 < N 個月支出」**，我沒有先做，因為那要有實測依據才知道 N 該設多少。
